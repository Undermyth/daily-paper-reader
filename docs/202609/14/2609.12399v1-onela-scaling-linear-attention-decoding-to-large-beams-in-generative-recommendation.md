## 摘要
生成式推荐（GR）依赖大束宽解码来生成数百个候选物品，这为递归线性注意力带来了新的扩展挑战。现有的线性注意力服务系统要么为每个束物化完整的递归状态，要么重复重放共享历史，导致显著的内存与流量开销。为解决这一问题，我们提出 OneLA，一种利用 GR 工作负载中共享提示与较短分叉后缀的线性注意力解码框架。具体而言，OneLA 使用单个共享的、由提示导出的状态，以及紧凑的、仅追加的分叉转移记录来表示所有束状态。利用这种表示，OneLA 仅计算每个解码步骤所需的状态信息，而无需为每个束重建完整的递归状态。此外，OneLA 使用轻量级祖先索引来跟踪构成每个束历史的转移记录，使得束可以在不移动或复制现有记录的情况下更新。融合 GPU 内核进一步跨束复用共享状态。我们的分析表明，OneLA 实现了 1.54-2.46 倍的端到端解码加速，同时大幅降低递归状态内存占用和数据移动。

## Abstract
Generative recommendation (GR) relies on large-beam decoding to generate hundreds of candidate items, creating a new scaling challenge for recurrent linear attention. Existing linear attention serving systems either materialize a full recurrent state for every beam or repeatedly replay shared history, incurring substantial memory and traffic overhead. To address this, we present OneLA, a linear-attention decoding framework that exploits the shared prompt and short divergent suffixes of GR workloads. Specifically, OneLA represents all beam states using a single shared prompt-derived state and compact, append-only records of their divergent transitions. Using this representation, OneLA computes only the state information required at each decoding step, without reconstructing a full recurrent state for every beam. Furthermore, OneLA uses a lightweight ancestry index to track the transition records that make up each beam's history, allowing beams to be updated without moving or copying existing records. A fused GPU kernel further reuses the shared state across beams. Our analysis shows that OneLA achieves 1.54-2.46x end-to-end decode speedups while substantially reducing recurrent-state memory use and data movement.

# OneLA 论文总结

## 1. 核心问题与整体含义

- **研究背景**：生成式推荐（GR）将物品表示为短序列的离散语义 ID（SID），把推荐转化为自回归序列生成。与常规 LLM 服务不同，GR 需要一次生成数百个候选物品，因此依赖**大束宽解码**：每步扩展所有活跃束并在全局选择 top-k。
- **新扩展瓶颈**：GR 工作负载具有“长共享 prompt + 短生成后缀 + 大且动态演化的束”的结构。线性注意力（如 Gated DeltaNet, GDN）虽将历史压缩为固定大小递归状态，避免 KV cache 随序列长度增长，但大束宽使“每个束一个独立递归状态”成为新的内存与带宽瓶颈。
- **现有系统不足**：
  - vLLM FullState：为每个活跃束物化完整递归状态，持久状态容量和读写流量随束宽急剧增长。
  - vLLM ReplaySSM：通过前缀重放减少状态持久化，但不区分长共享 prompt 与短解码阶段，可能留下大段 prompt tail 需重放；且把每个束当作独立请求，需分别加载 checkpoint 并重放。
  - SGLang、FlashInfer、TensorRT-LLM：仅提供 GDN 算子级支持，缺乏端到端 GDN + beam search 服务能力。
- **核心矛盾**：动态 beam selection 会重排、剪枝、复制束，而物化状态直接绑定逻辑束，导致状态复制、重建或重算。论文因此提出：**避免为每个束物化完整递归状态，并解耦逻辑束演化与物理状态放置**。

## 2. 方法论

### 2.1 核心思想

- 同一请求内所有候选束都源自**相同的 prompt 后递归状态** \(S_{\text{ctx}}\)，仅在解码阶段通过少量 GDN 状态转移发生分叉。
- 因此，OneLA 用“**一个共享的 prompt 后状态 + 紧凑的、仅追加的分叉转移记录**”表示所有束，而不是为每个束保存完整 \(d_v \times d_k\) 递归矩阵。
- 解码时不做完整状态重建，而是直接在两个状态投影上重放记录，按需计算当前步所需信息。

### 2.2 GDN Transition Record（GTR）

- GDN 状态更新可写为：
  \[
  S_t = \alpha_t S_{t-1} + \delta_t k_t^\top,\quad
  \delta_t = \beta_t(v_t - \alpha_t S_{t-1}k_t)
  \]
- 论文定义单步转移记录为：
  \[
  r_t = (\alpha_t,\ \delta_t,\ k_t)
  \]
  其中 \(\alpha_t\) 为标量衰减因子，\(\delta_t\) 为 \(d_v\) 维更新向量，\(k_t\) 为 \(d_k\) 维键向量。
- 每个 GTR 只需 \(O(d_v + d_k)\) 存储，而完整递归状态需 \(O(d_v d_k)\)。存储 \(\delta_t\) 而非 \((\beta_t, v_t)\)，是为了让记录贡献不再依赖父状态 \(S_{t-1}\)，从而避免使用记录前必须先重建父状态。

### 2.3 投影重放（Projection Replay）

- GDN 层与历史状态的交互只通过两个向量收缩：键投影 \(S_{t-1}k_t\) 和查询投影 \(S_{t-1}q_t\)。
- OneLA 沿束祖先链重放 GTR，直接维护两个投影累加器：
  \[
  u_q^{(j)} = S_j q_t,\quad u_k^{(j)} = S_j k_t
  \]
  从共享上下文开始：
  \[
  u_q^{(-1)} = S_{\text{ctx}}q_t,\quad
  u_q^{(j)} = \alpha_j u_q^{(j-1)} + \delta_j(k_j^\top q_t)
  \]
  键投影累加器同理。
- 重放完成后直接得到当前步所需投影：
  \[
  \delta_t = \beta_t(v_t - \alpha_t u_k^{(t-1)}),\quad
  o_t = \alpha_t u_q^{(t-1)} + \delta_t(k_t^\top q_t)
  \]
- 因此，重放只需两个 \(d_v\) 维累加器，无需物化任何中间 \(d_v \times d_k\) 递归矩阵，计算从矩阵级降为向量级。

### 2.4 动态束祖先索引

- GTR 以**仅追加**方式存放在原始物理槽位中，beam selection 只改变引用关系，不修改历史记录。
- 定义 \(h_t(b,j)\) 为束 \(b\) 在解码步 \(j\) 的 GTR 物理槽位，\(\pi_t(b)\) 为父束。祖先索引更新为：
  - 若 \(0 \le j < t-1\)：\(h_t(b,j) = h_{t-1}(\pi_t(b), j)\)
  - 若 \(j = t-1\)：\(h_t(b,j) = \pi_t(b)\)
- 子束复用父束的祖先索引，并记录父束上一步的物理槽位。剪枝只丢弃引用，重排只改顺序，扇出只复制祖先索引，**无需移动或复制历史 GTR 链**。

### 2.5 融合共享上下文 GPU 内核

- 每个 GPU thread block 负责一个 \(B_V\) 行的 value 维度 tile 和一组 beam。
- 块内一次性加载对应的 \(S_{\text{ctx}}[B_V, d_k]\) tile 到片上存储，并在多个 beam tile 间复用，避免每个束独立从 HBM 读取 \(S_{\text{ctx}}\)。
- 内核融合三件事：
  1. 共享上下文投影：初始化 \(u_q = S_{\text{ctx}}q_t\)、\(u_k = S_{\text{ctx}}k_t\)；
  2. 祖先感知重放：通过 \(h_t(b,j)\) 查找物理 GTR，直接更新两个投影累加器；
  3. 当前 GDN 更新与输出：计算 \(r_t\) 和 \(o_t\)，并只追加写回紧凑 GTR，而非完整状态矩阵。
- 中间值保留在片上，不物化到 HBM；最终只写 \(O(d_v + d_k)\) 的 GTR，消除每束完整状态写回开销。
