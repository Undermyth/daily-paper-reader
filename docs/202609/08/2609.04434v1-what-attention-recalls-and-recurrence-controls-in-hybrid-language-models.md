## 摘要
混合语言模型将注意力与固定大小的循环状态相结合，但每个通道的作用仍不清楚。我们引入了两种缓存级别的干预。Split-prefill（分割预填充）仅保留来自预填充上下文的KV缓存或仅保留循环状态，然后生成答案。State-swap（状态交换）在单次前向传递中将来自一个上下文的KV缓存与来自另一个上下文的循环状态配对。在Qwen3.5和Falcon-H1上，两个通道在功能上截然分开。精确检索仅通过注意力存活（完整准确率的64-98%），而通过循环则降至零。输出语言和人格则反转了这一模式：两者都通过循环存活（70-80%和3-5倍），而仅KV则降至约1%的语言准确率。State-swap因果性地证实了这一点：答案的值来自KV侧，而语言来自循环侧。仅循环生成也接受上下文中从未出现但与被看到的项目共享意义或部分的单词。注意力提供对所说内容的查找；循环状态则塑造模型接下来如何说。

## Abstract
Hybrid language models combine attention with a fixed-size recurrent state, but the role of each channel remains unclear. We introduce two cache-level interventions. Split-prefill keeps only the KV cache or only the recurrent state from a prefilled context, then generates an answer. State-swap pairs the KV cache from one context with the recurrent state from another in a single forward pass. On Qwen3.5 and Falcon-H1, the two channels split sharply by function. Exact retrieval survives only through attention (64-98% of full accuracy) and collapses to zero through recurrence. Output language and persona reverse the pattern: both survive recurrence (70-80% and 3-5x) while KV-only drops to ~1% language accuracy. State-swap confirms this causally: the answer takes its value from the KV side and its language from the recurrent side. Recurrent-only generation also accepts words that were never in the context but share meaning or parts with seen items. Attention provides a lookup over what was said; the recurrent state shapes how the model says it next.

## 1. 核心问题与研究动机

- 混合语言模型（Hybrid LM）结合了 softmax 注意力模块与固定大小规模的循环状态模块（如 Gated DeltaNet、Mamba），已被 Qwen3.5、Falcon-H1、Jamba 等开源模型采用。
- 当前关键机制问题在于：在推理时，注意力通道（KV cache）与循环通道（recurrent state）分别承担什么功能？已有工作普遍认为这种结构差异是“时间性”的——注意力是精确但昂贵的长期记忆，循环状态是廉价的短期缓冲。本文对该假设提出了挑战。
- 作者认为，两大通道的分离是**功能性**的：两者并非因信息"新/旧"有所区分，而是提供了**不同种类的访问机制**——注意力提供可寻址的内容查表（addressable lookup）；循环状态塑造模型后续的表达方式（语言、语气、人格等输出行为），而非内容的具体回忆。

## 2. 方法论：核心思想与技术细节

### 2.1 Split-prefill（分割预填充）
- 将输入提示拆成**上下文 c** 与**查询 q** 两部分；先对 c 做一次前向传播，得到并保存两种内部状态：
  - 注意力通道：KV 缓存 K(c)
  - 循环通道：R(c)（Qwen 上为 Gated DeltaNet 状态；Falcon 上为 Mamba SSM 状态）
- 随后在三种条件下运行 q：
  - **FULL**：同时保留 K(c) 与 R(c)
  - **KV-ONLY**：保留 K(c)，将 R(c) 置零
  - **REC-ONLY**：保留 R(c)，丢弃 KV 缓存
- 关键约束：q 三种条件下逐字节相同；FULL 与 KV-ONLY 下 q 从位置 |c| 开始，REC-ONLY 下因 KV 为空而从头开始（作者明确说明这是有意设计，以避免零填充键值引入第三类不受控条件）。
- 分割位置必须落在单一用户轮次内，保证 c∥q 与未干预时的推理输入完全一致，使 FULL 条件等同于普通推断。

### 2.2 State-swap（状态交换）
- 预填充两个格式相同、内容不同的上下文 cA、cB（两者各自携带独立的“键值字典”和“输出语言指令”），分别抽取 KV 缓存与循环状态。
- 在**单次前向传播**中组装混合缓存：K(cA) + R(cB) 及其镜像 K(cB) + R(cA)，共享同一查询 q。
- 若答案内容（如键值）跟随 cA、语言风格跟随 cB，即可将两种属性因果性地分别归因到注意力通道和循环通道。

### 2.3 "沉默失效"问题与验证协议
- 多数混合层公共实现仅在单 token 解码路径下恢复循环状态；若将 q 作为多 token 块一次输入，恢复的循环状态会被**静默忽略**，模型表现为"无上下文"，却不报任何错误。
- 若不加验证，REC-ONLY 的崩溃容易被误读为"循环通道不携带信息"。作者规定了强制验证协议：计算恢复状态与零状态在 logits 上的无穷范数差 Δ，Δ≈0 说明状态未真正进入模型，该配置的结果必须作废丢弃。实测中某一模型块式预填充下 Δ=0.0000，改用逐 token 方式后 Δ=12.1。
- 作者警示：状态交换实验中"同源对照"（K(cA)+R(cA)）看起来很健康并不代表状态被真正使用了——仅 KV 通道本身可能已足以解释输出。

### 2.4 核心实现细节
- 上下文先做一次预填充；所有消融条件复用同一次预填充状态，不重复截断运行。
- 解码采用贪心（argmax）策略；检索类任务限 8 token（单词答案），语言/人格类自由文本限 48 token。
- 语言评分用 fastText lid.176 语言识别模型；人格评分用与受测模型**不同家族**的 Qwen2.5-72B-Instruct 做评判模型。
- 每类条件共享查询、提示与解码器，保证差异不可能来自解码方式。

## 3. 实验设计

### 3.1 诊断任务（benchmark 构建）
作者刻意放弃标准长上下文评测集（因这类任务同时要求 token 检索与响应模式维持，无法将精度下降归因到具体功能），改为四个小规模合成任务，每任务隔离一种能力：

| 任务 | 能力 | 构造方式 |
|---|---|---|
| KV retrieve | 精确键值查找 | 15-30 条短 ASCII 键值对字典，询问某键对应值 |
| List indexing | 位置检索 | 4-10 个条目列表，询问某位置元素 |
| Language following | 行为指令跟随 | “仅用 L 语言回答”指令 + 其他语言提问，用语言分类器评测输出语言 |
| Persona | 风格模仿 | 15 种人格描述（海盗、巫师等）搭配中性问题，独立 LLM 评判风格匹配度 |

### 3.2 四个因果案例分析（Case Studies）
- **Case 1 — Mixed Memories（状态交换）**：双重交叉实验，左右两个上下文同时携带不同的字典和不同的语言指令。每个方向 300 个测试（100×3 seeds）。
- **Case 2 — Recall but Not Control**：区分"命名指令语言"与"实际遵循指令"两种能力。20 种语言的自报告探针，每种 20 例。
- **Case 3 — Associative False Recall（DRM 范式）**：100 组语义关联词表，验证 REC-ONLY 是否错误"接受"与词表语义相关但实际未出现的目标词（如词表含 bed、rest、pillow…，询问 "sleep" 是否出现，标准答案为否）。
- **Case 4 — Conjunction Trap（记忆拼接错误）**：200 个特征拼接项，词表含 sunflower 与 moonlight，询问 "sunlight" 是否出现；附带单特征缺失、无关缺失、真出现等多类对照。

### 3.3 被测模型
- 主实验：Qwen3.5-4B（Gated DeltaNet）、Falcon-H1-3B-Instruct（Mamba）
- 扩展实验：Qwen3.5-9B/27B、Falcon-H1-7B/34B、Kimi-Linear-48B、Olmo-Hybrid-7B、Jamba2-3B
- 层域消融（Qwen3.5-4B）：LOWER-KV+FULL-REC（仅保留下半层注意力 KV 而循环状态完整）与 FULL-KV+LOWER-REC（KV 完整、仅保留下半层循环状态）

## 6. 主要结论与发现

- **精确检索仅通过注意力存活**：KV-ONLY 保留基线 64-98% 准确率（随模型变大单调提升）；REC-ONLY 在全部模型的检索任务上**一致精确地坍塌到 0**（0/600 每 seed 每模型），即便在极短的字典/列表场景下依然如此——排除了"状态太小存不下"的解释。
- **语言与人格由循环状态掌控**：行为任务上顺序翻转——REC-ONLY 保留 FULL 的语言跟随准确率（70-83%；不同模型间波动为 41-83%），KV-ONLY 在语言跟随上坍塌至约 1%（个别大模型可达 25-31%）；人格表现同方向（REC-ONLY 为 KV-ONLY 的 3-5 倍）。
- **因果性验证（状态交换）**：K(cA)+R(cB) 的混合脑状态下，模型产出一句流畅回答——**被检索的值取自 cA（KV 源），而语言采用 cB（循环源）所要求的语言**。两个方向上联合正确率：Qwen3.5-4B/9B 为 100%，Falcon-H1-3B ≈99%，Falcon-H1-7B ≈87-89%。同源对照（K(cA)+R(cA)）几乎全部达到 100%。
- **"能命名 ≠ 能服从"**：KV-ONLY 下模型可以准确说出"要求的语言是什么"（英文名称 50-100%），却无法实际用那种语言回答（约 0.05）；REC-ONLY 则相反——说不出语言名称，却能以目标语言流畅作答。指令的**陈述性记忆**（在 KV 中）与**程序性执行**（经循环状态）是两回事。
- **循环状态易于语义假忆**：REC-ONLY 在 DRM 关联词表上高比例误报未出现的语义关联词（最高达 0.87-0.99），对照的中性无关词表则保持低位（Falcon-H1-7B 例外）；KV-ONLY 正确拒绝绝大多数关联陷阱。
- **特征级存储但绑定丢失**：REC-ONLY 会把两个已见成分的组合（sunflower + moonlight → "sunlight"）误认为出现过的原词，且该信号需要两个部分同时在场才显著；说明循环状态保留的是语义场与成分特征，丢失的是"绑定为具体条目"的能力。
- **层域消融支持通道归因**：检索要求 KV 完整保留，行为转移要求循环状态完整保留，该模式在层级别同样成立。

总体断言：在已训练好的混合 LM 中，两通道之分不在于"记多久"，而在于"如何访问"——KV 缓存是可寻址的记忆存储；循环状态是控制语言风格、人格与语义场的压缩先验。此分工类似认知心理学中 Tulving / Schacter 提出的外显/内隐记忆区分。

## 7. 方法优点

- **真正的因果干预而非关联分析**：在单次前向传播中通过状态交换实现严格对照——两个通道都来自真实预填充的合法上下文，只是来源上下文不同，规避了单个缓存重置造成的分布外问题这一主要混淆。
- **发现了"静默失效"这一隐性坑，并设定强制验证协议**（Δ>0 检查），方法工程上严谨可复现。这类实现陷阱极易导致全表数据无效而研究者不自知，本文的处理具有方法论示范价值。
- **对任务设计的反向思考**：不选用现有标准基准而是精心设计小任务"每种能力隔离一种函数"，用效应量补偿规模缺失，理由充分明确。
- **效应量巨大**（检索从 0.98 直接到 0.00、语言 KV 侧约为 0.01 vs 循环侧 0.79），且在三代架构（Gated DeltaNet、Mamba、SSM/linear-attention 变体）与 3B 到 48B 的多个模型上稳定复现；四组"演示"中均配多级对照（"标签 vs. 行为"、"同源 vs. 交叉"、"单缺/双缺 vs. 全组合"），排除替代解释的能力很强。
- **细致区分"编码了什么"与"控制了什么"**——限制声明明确指出结论是功能性的因果归属，不是静态内容清空；Falcon-H1-3B/7B 与 Language-following 等个别反例未隐藏，属于诚实报告。
- **与人类记忆心理学理论（外显/内隐、DRM 假记忆、记忆拼接错误）的类比自然且具有启发力**，将 ML 机制分析与认知科学文献连接。

## 8. 不足与局限

### 8.1 功能性 vs. 静态内容
- 结果显示各通道在推理时的因果贡献，但并不等于该通道内不存储另一类信息。作者在 Limitations 中直接承认：KV-ONLY 下模型能"说出要求的语言名称"（检索到指令）却无法执行它，证明 KV 中确有语言指令相关内容——故"KV 不含语言信息"说法不成立，准确表述是"KV 中的语言信息不足以驱动行为生成"。
- 通道**内部**究竟静态编码了什么仍属未知；作者将激活探针类分析留给未来工作。

### 8.2 干预本身制造分布外状态
- Split-prefill 将一侧状态置零、另一侧保留，产生模型未曾在训练中见过的缓存组合方式，可能部分解释某些模式的崩溃。状态交换实验（两边均合法）对此有缓解，但不能完全排除。
- 只关注了**非推理模型**或指令微调模型？论文以 Qwen3.5-**Instruct** 与 Falcon-H1-**Instruct** 为主（虽然提及无后缀的 Qwen3.5-4B），未能明确区分基座模型与指令微调模型行为差异；若实验在基础模型上做，行为类结论（语言、人格转移）未必逐一成立。

### 8.3 任务生态效度
- 合成任务刻意缩小和简化，"字典、列表、单一指令"不能完整覆盖真实世界的复杂语境。长期语境（数万 token 以上的叙事、代码、多轮对话）中的通道分工是否沿用本文结论，尚未验证。
- 语言跟随任务通过 fastText 判定输出语言，粒度限于 18 种常见语言，未覆盖代码切换、创造性写作、技术文体等更细的输出行为维度。

### 8.4 实验覆盖的缺口
- Falcon-H1 上未实现层域消融模式（作者标注 "these modes were not implemented for Falcon-H1"），层级的内部异质性只在 Qwen 侧验证。
- 大模型扩展（27B/34B+）仅有单 seed 数据（作者用 ‡ 标注），跨 seed 变异未被量化。
- Jamba2-3B 的同源对照仅达 86-89%，清晰度不如主模型，作者未就此展开解释。
- 个别异常：Falcon-H1-7B 的 KV-ONLY 在 DRM 假记忆上与 REC-ONLY 存在重叠（reported >0.55），表明至少某些模型的 KV 通道也有一种"宽泛的熟悉感"，作者解释为普遍性易感性但未再深入。

### 8.5 工程与应用限制
- 干预需要在推理路径上提取和跨上下文装配缓存，这要求模型实现接口支持显式 KV/循环状态，**不能立即应用于闭源 API 模型**。
- 验证协议（逐 token 解码、Δ 检查）增加技术门槛；不同库版本可能不兼容并产生静默退化，影响可复现性。
- 对视觉-语言混合模型、纯循环模型（无注意力通道）等应用边界尚待验证。
