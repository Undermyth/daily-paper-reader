## 摘要
语言模型将大部分注意力集中在上下文的很小一部分上，却仍需读取整个KV缓存以找到少数关键token。当用户询问百万级token对话中的某个先前细节时，全局注意力层必须扫描完整上下文才能生成回复的每一个token。一种主流方法通过轻量级代理分数预先选择相关token来缓解这一开销，但这种外在评分仍每一步需花费O(N)的时间。我们采取一种内在方法，源于一个简单问题：模型难道不是已经知道上下文的哪些部分是相关的吗？为此，我们引入声明式注意力（DA），该协议引导模型在其思维链中声明需要关注的位置，将生成过程划分为三种模式：<global>（完整上下文）、<focus>（特定区域）和<local>（仅最近输出）。推理引擎像处理工具调用一样解析这些声明，并跳过大部分KV缓存读取。在15项长上下文任务的零样本评估中，DA在现成模型（Gemma-4-31B、Qwen-3.6-27B）上显著减少了解码期间的总注意力token数（52.0%、31.1%），准确率下降幅度不大（1.27个百分点、2.75个百分点），且随模型规模扩大而缩小。DA为稀疏注意力开辟了新的维度，未来基于训练的方法可能进一步发掘其潜力。

## Abstract
Language models spend most of their attention on a small fraction of context, yet they read the entire KV cache to find the few tokens that matter. If the user asks about a previous detail in a 1M-token conversation, global attention layers must scan the full context to generate each token of the reply. A prominent approach mitigates this cost by pre-selecting relevant tokens via lightweight proxy scores, but this extrinsic scoring still incurs O(N) per step. We take an intrinsic approach motivated by the simple question: wouldn't the model already know which parts of the context are relevant? To this end, we introduce Declarative Attention (DA), a protocol that elicits the model to declare where it needs to attend within its chain-of-thought, partitioning generation into three modes: <global> (full context), <focus> (a specific region), and <local> (recent output only). The inference engine parses these declarations like tool calls and skips most of the KV cache read. Under zero-shot evaluation across 15 long-context tasks, DA on off-the-shelf models (Gemma-4-31B, Qwen-3.6-27B) significantly reduces total attended tokens during decoding (52.0%, 31.1%) with modest accuracy drops (1.27pp, 2.75pp) that shrink with model scale. DA unlocks a new axis of sparse attention, with further potential under training-based methods that future work can explore.

## 一、论文的核心问题与整体含义

- 研究动机：Transformer 在每个解码步骤中都要对所有前序 token 计算注意力，使得长上下文解码时 KV cache 的内存访问成为主要开销。然而大量实证研究表明，模型实际只关注上下文中很小一部分 token。现有稀疏注意力方法（如基于代理分数预选 token）仍需每步执行 O(N) 的轻量扫描或索引，未从根本上消除上下文长度的线性开销。
- 核心问题：能否让模型自身在生成过程中“说出”它下一步需要关注的位置，从而直接省去外部评分和扫描？
- 整体含义：论文提出一种全新的、正交于现有稀疏注意力路线的方案——声明式注意力（Declarative Attention, DA）。它让模型以可解析的控制标签形式，在其思维链中声明注意力范围，推理引擎依据声明只读取相关 KV 块。作者证明这种能力可以零样本地从现成模型中激发，无需训练，为高效长上下文推理开辟了新方向。

## 二、方法论

- 核心思想：把注意力选择从“模型内部隐含的、需近似推断的模式”转变为“模型在文本中显式声明的策略”。其灵感来源于两方面的观察：(1) 模型隐藏状态中已包含对未来 token 的信息； (2) 思维链可以将潜在计算暴露为可解释文本。DA 将这一原则从“决定思考什么”扩展到“决定关注哪里”。
- 三种注意力模式：
  - `<global>`：关注全部上下文，用于定位/导航，模型在此模式下说明接下来应聚焦哪个片段。
  - `<focus magic_chunks="K">`：只关注第 K 个上下文片段（magic chunk），用于从指定区域中提取信息。
  - `<local>`：不关注任何上下文片段，只关注自身已生成的回复、问题和指令，用于基于已提取信息的推理和答案合成。
- 模型输出示意（具可解析性）：
  - `<global>` 定位 → `<focus>` 提取 → `<global>` 再定位 → `<focus>` 再提取 → `<local>` 综合 → `<answer>` 输出。
- Prompt 结构：
  - 分为“脚手架”（始终可见）和“上下文”（动态掩蔽）两部分；脚手架包括系统指令、问题和 DA 使用指令。
  - 系统指令中放置 attention sink，使注意力汇聚不进入实质上下文。
  - 上下文被分割为约 2K token 的“magic chunks”，并以“模拟工具调用”格式呈现（工具名 `get_magic_chunk`），段边界放置在模型训练时熟悉的 turn/tool 特殊 token 上，使模型能自然追踪。
- 解码期干预：
  - 设计 DA 状态机解析输出流中的标签开关，更新注意力掩码。
  - 掩码以 vLLM 的 KV cache block 粒度对齐（外扩至 block 边界，避免读入多余块）。
  - 集成方式：在 vLLM 注意力元数据构建器上加 hook，重写 block table，不修改内核或调度器；兼容 FlashAttention。
  - 仅作用于全局注意力层；滑动窗口注意力、Gated DeltaNet 等高效层不受影响。
- 成本/效益分析框架：
  - 提出 roofline wall-time 模型：FFN 在大 batch 下为计算受限，注意力为内存受限；长上下文中，注意力 KV 读取占解码主导成本，DA 削减的就是这一项。
  - 无新增每步 O(N) 开销：解析 `<focus>` 为 O(1)，只在 `<global>` 模式保留完整读取。

## 六、主要结论与发现

- 零样本 DA 大幅降低解码注意力成本：在 Gemma-4-31B 上总 attention token 减少 52.0%，准确率下降 1.27 个百分点；在 Qwen-3.6-27B 上减少 31.1%，准确率下降 2.75 个百分点。
- 效率提升全部来自掩码机制：DA nm 使用相同 prompt 但无掩码时，因为生成了更多 token（约 15–35% 额外步骤），注意力读取反而高于 vanilla（Gemma 上高 66.2%）；施加掩码后，相对 DA nm 减少 71.1%（Gemma）和 46.5%（Qwen）。
- 模型规模越大，DA 相对准确率越接近 vanilla：Gemma 系从 29%（E4B）升至 99%（31B），Qwen 系从 64%（4B）升至 97%（27B）。
- 上下文越长，绝对 token 节约越大（最长上下文桶节约约 21M token/回复），相对节约接近恒定（约 50–64% of vanilla）。
- 模式分析：模型约 73% 的生成 token 落在 focus/local 廉价模式，每 token 注意力节约 76–99%，且随上下文长度增加显著；local 模式最省，focus 次之。
- Roofline 分析：理论上，在优化的分离式推理栈中，DA 可将解码墙钟时间降至 vanilla 的 0.71×（Gemma-4-31B）和 0.77×（Qwen-3.6-27B）。
- 协议遵循率随规模上升，最大模型 focus 成功率达 99% 左右；最小模型失败率较高，是准确率崩塌的主要原因。

## 七、优点

- 概念新颖且优雅：把“注意力选择”从需外部代理估计的隐性计算变为模型以自然语言显式表达的可解析声明，直接免除每步 O(N) 得分开销。
- 零样本协议，无需训练即可在现成模型上工作；与需要特化训练的 SSAS 形成重要差异。
- 良好实验设计：
  - 使用 DA nm 精巧地分离 prompt 格式与掩码的贡献；
  - 多模型、多尺寸、多上下文长度全面分析；
  - 对失败案例进行诚实报告与原因分类；
  - 详细报告模型能否稳定地遵循协议。
- 与现有系统兼容性好：集成到 vLLM 时无需改内核，掩码以 block table 重写完成，天然兼容 FlashAttention、推测解码等加速手段，也为 KV cache offloading 提供了可预取模式的可能。
- 开创新方向：将稀疏注意力升维为“系统-2 稀疏注意力”，具备可解释、可审计、可由强化学习进一步优化的潜力。

## 八、不足与局限

- 零样本 elicitation 导致协议开销：
  - DA 比 vanilla 多生成约 15–35% 的 decode token，部分抵消 token 节约；
  - 未使用思维（thinking）模式，模型在 thinking 轨迹中无法可靠遵循协议；
  - 模型选择模式的策略不一定最优，global 模式仍可能使用过多（且 QA 规模稍大时 global 占比上升）。
- 上下文分块是人为的：
  - 基准静态长文本被分割成人工 “magic chunks”，可能破坏跨段完整性（例如表格被切开、全局计数类问题无法回答）。
  - 真实智能体场景中天然有工具调用/轮次级边界，但该论文暂未验证。
- 评估覆盖有一定局限：
  - 已排除多类源（比如硬性禁止中间推理的 RULER 任务、输出长度随文档增长的摘要/排序任务）；
  - 在主结果 15 任务之外，附录显示 6 个失败任务中 DA 准确率显著下降或 token 节约不理想，而主表未包含这些任务，总体上可能高估 DA 的平均表现。
- 对 masked 前的假设依赖较强：
  - DA 依赖模型在输出文本中准确描述其真实注意力意图；如果声明与真实所需不一致（如模型“猜”了错误 chunk），accuracy 会下降。
  - 协议只降低全局注意力层、仅对以 KV 读取为主的内存受限系统有效；在 FFN 与注意力未分离部署的低并发场景收益会缩水。
- 缺少实测墙钟时间：
  - 效率数字为 roofline 理论估计，未做真实延迟/吞吐实验，也未报告实际 B200 实测数据；附录承认低并发下自身 kernel 利用率远低于 70% MBU。
