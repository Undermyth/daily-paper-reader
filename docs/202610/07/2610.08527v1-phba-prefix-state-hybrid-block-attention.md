## 摘要
将线性序列模型与 softmax 注意力相结合的混合架构，在高效的长上下文建模与精确的词元检索之间取得了有效平衡。现有的设计（如原生混合注意力，NHA）将压缩的长期状态与滑动窗口注意力相结合，但其精确注意力被限制在固定的局部窗口内。在本工作中，我们提出前缀状态混合块注意力（PHBA），它用 top-k 块稀疏检索取代局部滑动窗口注意力，并将每个检索到的块与一个紧凑的前缀状态相耦合，该状态概括了其前文上下文。前缀状态由块边界处的门控线性递归构建，并与相应的词元块一同被检索，使模型能够在统一的层内将精确的长程证据与压缩的历史上下文相结合。我们进一步开发了一种硬件感知的 Triton 实现，它以流式方式处理路由的词元块和前缀状态，而无需具体化大型中间张量。实验表明，PHBA 在长上下文与检索性能上优于强线性与混合基线，同时保持了高效的训练与推理。

## Abstract
Hybrid architectures combining linear sequence models with softmax attention provide an effective balance between efficient long-context modeling and precise token retrieval. Existing designs such as Native Hybrid Attention (NHA) combine compressed long-term states with sliding-window attention, but their exact attention is restricted to a fixed local window. In this work, we introduce Prefix-State Hybrid Block Attention (PHBA), which replaces local sliding-window attention with top-k block-sparse retrieval and couples each retrieved block with a compact prefix state summarizing its preceding context. The prefix states are constructed by a gated linear recurrence at block boundaries and retrieved together with the corresponding token blocks, allowing the model to combine precise long-range evidence with compressed historical context within a unified layer. We further develop a hardware-aware Triton implementation that streams routed token blocks and prefix states without materializing large intermediate tensors. Experiments show that PHBA improves long-context and retrieval performance over strong linear and hybrid baselines while retaining efficient training and inference.

# PHBA: Prefix-State Hybrid Block Attention 论文总结

## 1. 核心问题与研究动机

- **背景**：长上下文语言建模需要同时满足两个目标——高效处理超长序列，以及从远距离位置可靠地检索信息。
- **现有矛盾**：
  - 标准 softmax 自注意力（Transformer）提供精确的 token 级全局访问，但复杂度随上下文长度二次增长。
  - 线性/循环序列模型（Mamba、GLA、GSA、RetNet 等）将历史压缩到固定大小的状态，效率高但牺牲了精确的上下文内检索能力。
  - 混合架构（如 NHA）将压缩的循环状态与滑动窗口注意力（SWA）结合，但**精确注意力被限制在固定的局部窗口内**，窗口外的 KV 只能通过压缩状态访问，无法按内容相关性分配注意力预算。
- **核心挑战**：能否让稀疏注意力为每个 query 检索全局相关的 KV 内容，同时保留其前文上下文？
- **切入点**：借鉴 MoBA 的查询相关块级路由，用 top-k 块稀疏检索替代固定滑动窗口，并为每个检索块配一个"块对齐前缀状态"。

## 2. 方法论

### 2.1 核心思想
在同一层内联合使用两类记忆：
- **精确 token 记忆**：通过 top-K 块路由选出的历史块中的原始 token（高分辨率证据）。
- **压缩前缀状态记忆**：由块边界的门控线性递归生成，概括该块之前的因果历史（块对齐的压缩上下文）。

两类记忆共享一次 softmax 归一化，使每个 query 直接在"精确证据"与"压缩历史"之间分配概率质量，而非通过外部融合权重。

### 2.2 关键技术细节

- **Top-K 块路由（Sec 3.1）**
  - 将序列划分为 Nc 个、每块至多 C 个 token 的连续块。
  - 用块内 RoPE 键的均值作为块质心：`k̄_b^rope = (1/|B_b|) Σ k_i^rope`。
  - 每个 query 只在**当前块之前**的块中选相似度最高的 Kh = K−1 个历史块；当前块始终保留用于局部因果注意力。
  - 质心仅用于路由，选中后仍访问原始 token 级 KV。

- **前缀状态构建（Sec 3.2）**
  - 采用 GSA 的门控槽记忆，保留门 `A_t = σ(a_t)^{1/τ}`，写门 `I_t = 1 − A_t`。
  - 前缀键/值状态更新：`S_t^K = Diag(A_t)S_{t−1}^K + I_t(k_t^raw)^T`，值状态同理，键值槽共享同一组门以保证时间对齐。
  - 在块 B_b 起始位置 τ_b 处存储状态：`P_b^K = S_{τ_b−1}^K`，`P_b^V = S_{τ_b−1}^V`——即该块之前的因果前缀，不含本块 token。
  - 无因果前缀的块对应状态被 mask 掉。

- **Online-Softmax 词元–状态注意力（Sec 3.3）**
  - token 分支用 RoPE query/key：`ℓ_t,i^tok = (q_t^rope)^T k_i^rope / √d`。
  - 前缀状态分支用原始 query/前缀状态 key：`ℓ_t,b,m^st = (q_t^raw)^T p_b,m^K / √d`。
  - 两分支各自维护 online-softmax 统计量，再通过 log-sum-exp 合并：
    - `L_t = LSE(L_t^tok, L_t^st)`
    - `O_t = e^{L_t^tok − L_t} O_t^tok + e^{L_t^st − L_t} O_t^st`
  - 该合并**精确等价于**对两类记忆并集做单一 softmax，避免显式拼接。

- **硬件高效分块并行与稀疏执行（Sec 3.4）**
  - **分块前缀状态更新**：仅边界状态跨块递归，块内写入并行计算：
    - `S[n+1] = Diag(∏A[n]) S[n] + W[n]^T Z[n]`，其中 `W[n] = I[n] ⊙ ←A[n]`。
    - 用 log A 的块内前缀和构造累积保留因子以保证数值稳定。
  - **算子感知稀疏执行**：不物化打包的稀疏载荷张量，仅物化紧凑整数路由元数据，直接从原始 HBM 布局流式加载 query 行、token 块与前缀状态块到 SRAM/寄存器。
  - 前向：先用块局部因果 FlashAttention 计算输出与 LSE 种子，再由融合稀疏核扩展 online-softmax 累加器。
  - 反向：将 query-centric 路由重排为 block-major 变长元数据（ρ、Offset、C_blk），按块枚举访问行，避免物化稀疏概率张量。

## 3. 实验设计

### 3.1 模型与训练
- 两个规模：**760M（50B tokens）** 与 **1.3B（100B tokens）**，均从头在 **FineWeb-Edu** 上训练，上下文长度 **8K**。
- 默认配置：M = 128 前缀状态槽，块大小 C = 128；1.3B 主对比使用固定 **1/8 精确 token 预算**（K = 8 块）。
- 隐藏维度 1536/2048，head dim 128，16 个注意力头，MLP 扩展比 4，32K SentencePiece 分词器。

### 3.2 对比基线
- Transformer（全注意力）、MoBA（块路由稀疏）、GSA（门控槽记忆）、KDA（Kimi 线性注意力）、NHA（混合注意力）。
- 所有基线使用相同数据、上下文长度和匹配的模型规模，稀疏方法使用匹配的精确 token 预算。

### 3.3 评估基准
- **短上下文（8K 内）**：WikiText、LAMBADA、零样本常识推理（ARC-e/c、HellaSwag、PIQA、WinoGrande）、RULER/NIAH（4K、8K），使用 lm-evaluation-harness。
- **长上下文（外推至 16K/32K/64K，不额外训练）**：RULER（CWE、HotpotQA、SQuAD）、NIAH（单键/多键/多查询/多值）、LongBench（文档 QA、摘要、少样本、代码；超 8K 截断取首尾各 4K）。
- **消融**：块粒度（C = 64/128/256/512）、前缀状态容量（M = 64/128/256）、门控状态构造（无门控 / 均值 / 门控）。
- **效率**：单卡 H20-96GB 上测 2K–16K 序列的端到端训练吞吐（Kt/s）。

## 6. 主要结论与发现

- **短上下文**：1.3B 下 PHBA 取得最佳 WikiText（15.21 ppl）与 LAMBADA（49.27 acc），常识平均 60.07 仅次于 KDA；RULER/NIAH 一致优于其他高效基线，仅落后于稠密 Transformer。
- **长上下文外推**：16K–64K 上保持最强的 RULER 与 NIAH 表现，优势随超出训练长度而更明显，说明"内容相关路由 + 块对齐前缀状态"对长上下文外推有效。
- **真实理解**：LongBench 平均分最高（18.14），在文档 QA、摘要、少样本任务上均有提升。
- **消融结论**：
  - 固定 1/8 预算下，更小 C + 更大 K 通常提升检索，但吞吐下降；C=128、K=8 为质量–效率折中。
  - 性能对 M 非单调，M=128 最稳；M 过小容量不足，过大无一致收益。
  - 学习式门控递归显著优于无门控与均值聚合，尤其在长上下文外推下。
- **效率**：匹配 1/8 预算下，PHBA 在 2K 时比 NHA 快 18.4–34.6%；相对 MoBA，加入前缀状态仅带来 6.7–11.9% 开销（C=256）；K=4 时 16K 达 8.79 Kt/s，比全注意力高 12.8%。

## 7. 优点

- **设计创新**：将"块对齐前缀状态"与"内容相关块路由"耦合，使每个被检索块都自带其前文压缩摘要，弥补了纯稀疏检索缺上下文、纯循环压缩缺精度的缺陷。
- **统一归一化**：token 与状态两分支共享一次 softmax，通过 online-softmax 精确合并，避免外部融合权重，理论上更优雅。
- **系统实现**：Triton 实现避免物化打包稀疏载荷，仅传整数元数据，块内并行 + 边界递归的分块方案兼顾训练效率与数值稳定。
- **实验严谨性**：token 预算匹配、相同数据/上下文、覆盖质量与效率双维度，消融维度选取合理（块粒度、状态容量、门控方式）。
- **可复现性**：提供完整伪代码、分块推导、训练/评估/基准测试协议，承诺开源代码。

## 8. 不足与局限

- **规模限制**：仅在 760M 和 1.3B 规模验证，缺乏更大模型（如 7B+）与更长训练 token 的证据，缩放规律未知。
- **长上下文绝对表现偏低**：部分 RULER 子任务（如 CWE 在 32K 仅 26.0）与 NIAH 多键任务分数仍低，长上下文能力上限存疑。
