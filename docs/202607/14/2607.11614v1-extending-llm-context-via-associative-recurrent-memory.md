## 摘要
扩展大语言模型（LLM）的上下文长度对于许多实际应用至关重要，但标准Transformer仍受限于二次计算和线性内存扩展。在本工作中，我们研究了联想循环记忆变换器（ARMT）作为一种实用方法，用于在LLM中实现长上下文处理、恒定内存扩展以及更好的效率。我们做出了三项主要贡献。首先，我们构建了两个特定领域的长上下文数据集，旨在评估现实工作负载，专注于窄域微调场景。其次，我们提出了一套基于ARMT的上下文扩展综合训练方案，结合了持续预训练、合成长上下文数据生成、课程学习以及将联想记忆选择性集成到所选模型层中。第三，我们进行了广泛的实验研究，表明ARMT增强模型：(i) 能够处理远超其原始上下文限制的输入，且性能相对于限制内基线没有下降；(ii) 能更有效地泛化到分布外的上下文长度；(iii) 在保持原始上下文窗口内基线性能的同时，所需FLOPs减少30%。

## Abstract
Extending the context length of large language models (LLMs) is critical for many real-world applications, yet standard transformers remain constrained by quadratic compute and linear memory scaling. In this work, we investigate the Associative Recurrent Memory Transformer (ARMT) as a practical approach for enabling long-context processing in LLMs, constant memory scaling, and better efficiency. We make three main contributions. First, we construct two domain-specific long-context datasets designed to evaluate realistic workloads, focusing on narrow-domain fine-tuning scenarios. Second, we propose a comprehensive training recipe for ARMT-based context extension, combining continued pre-training, synthetic long-context data generation, curriculum learning, and selective integration of associative memory into chosen model layers. Third, we present an extensive experimental study demonstrating that ARMT-augmented models: (i) process inputs well beyond their original context limits without degrading performance relative to in-limit baselines; (ii) generalize more effectively to out-of-distribution context lengths; and (iii) need 30% less FLOPs while preserving baseline performance within the original context window.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究动机**：标准Transformer架构在处理长上下文时面临两个核心瓶颈：自注意力机制的**计算复杂度随序列长度二次增长**，内存消耗线性增加，导致难以扩展到数十万甚至上百万token；此外，性能随上下文长度增加而显著下降（如"Lost in the Middle"现象）。
- **整体含义**：为了在隐私敏感场景（不能依赖远程API）、领域特定任务中实现高效长上下文处理，需要一种既能保留Transformer强短上下文能力，又能以**线性计算和恒定内存**扩展上下文的方法。ARMT（联想循环记忆变换器）通过段级循环记忆机制，结合全注意力（短时工作记忆）与联想记忆（长期记忆），被提出作为实用解决方案。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
ARMT将输入文本划分为固定长度的**非重叠段**（segment），每个段内使用**全注意力**建模局部上下文；同时引入**段级联想记忆模块**，在段之间通过可训练的记忆嵌入传播关键信息，使得模型能够跨任意长度上下文进行信息回忆，而避免全局二次注意力。

### 关键技术细节
- **架构组成**（参见图1）：
  - 基础LLM（如Gemma-3-1B-IT）作为骨干。
  - 输入被分成若干段，每段附加可训练的**记忆嵌入**（Mem）。
  - 每个Transformer层后接**联想块**（Associative Block），负责从当前段提取记忆、更新联想矩阵、为下一段提供关联向量。

- **联想记忆机制三步流程**：
  1. **记忆提取**：每个Transformer层将输入段压缩为记忆嵌入。
  2. **记忆巩固**：记忆嵌入作为键-值对存入层级的联想矩阵（associative matrix）。
  3. **关联**：下一段的每个嵌入转换为查询向量，与联想矩阵相乘得到关联信息。

- **训练方案四要素**：
  1. **持续预训练**：将ARMT添加到预训练LLM后，先用长文本（8段）进行无监督语言建模预训练（19B tokens FineWeb-Edu），初始化记忆参数。
  2. **合成长上下文数据生成**：从原始文档中采样多个短段落，为每个段落生成QA对，然后拼接成最长64k token的长上下文，增加训练样本多样性。
  3. **课程学习**：逐步增加上下文长度（2段→4段→8段），并伴随学习率退火，使模型逐渐学习跨段信息传播。
  4. **联想层剪枝**：仅保留部分Transformer层中的联想块（约20%的层），其余层使用恒等映射，可减少训练参数约30%并加速训练。

- **推理效率**：由于注意力仅在固定小段内进行全局计算（段大小S=1024），全局注意力FLOPs比全序列注意力减少约T/S倍（对T=32k，S=1k时减少32倍）。结合前馈层后，总FLOPs比原生Gemma-3-1B减少约30%。

## 3. 实验设计

### 使用数据集/场景
- **ManyTypes-long（MT）**：代码变量类型预测任务，从ManyTypes4Py构建，将同一仓库的代码脚本堆叠得到最长64k token的长文本，标签为变量类型（精确匹配）。
- **GovReport-long（GR / GR-100+）**：长文档问答任务，基于GovReport-QS，将相关段落与无关段落混合构建最长64k上下文，答案自由文本（ROUGE-L评估）。GR-100+是通过合成数据增强的版本（合成与真实样本比约5.5:1）。
- 其他基准：**BABILong**（推理寻物任务）、**ContractNLI**（长文档自然语言推理，SCROLLS基准）。

### Benchmark与对比方法
- **基线模型**：

## 6. 主要结论与发现

1. **上下文扩展能力**：ARMT模型能处理远超原始上下文限制（如32k→65k）的输入，且性能不降。在OOD和Long-OOD区间显著优于Base模型（如MT上Long-OOD EM 0.741 vs Base 0.463）。
2. **计算效率**：ARMT实现**恒定GPU内存**（不随上下文增长），并节省约30% FLOPs，同时保持批大小可扩大至4倍。
3. **联想层剪枝有效**：仅使用约20%的层（预选择规则：两个中间层、最后一层、首尾各一层）即可匹配甚至超越全ARMT性能，减少30%训练参数。
4. **持续预训练带来提升**：在FineWeb-Edu上持续预训练19B tokens显著提高ARMT在长上下文上的性能。
5. **合成数据帮助有限但稳定**：合成数据扩充至一定规模后，性能提升饱和。
6. **ARMT优于其他长序列模型**：在长上下文泛化方面强于Mamba-2、DeltaNet等，特别是从短训练长度泛化到极长输入。

## 7. 优点

- **方法创新性**：将联想记忆机制与段级处理结合，保留Transformer强大局部注意力，同时实现线性计算和恒定内存，不牺牲短上下文性能。
- **实用导向**：聚焦小型模型（1B参数）的领域特定部署，适用于隐私敏感场景；训练方案兼容LoRA，降低资源门槛。
- **实验完整**：包含丰富的消融、层分析、不同骨干、多个基准，结果较为稳健。
- **层预选择策略**：提出通用规则，避免每次需跑全模型确定重要层，具有实际可用性。
- **开源数据集**：构建了MT-long和GR-long两个领域长上下文数据集，可促进后续研究。

## 8. 不足与局限

- **模型规模局限**：仅验证到1B参数，未在更大模型（7B、70B）上评估，扩展性存疑。
- **任务覆盖有限**：仅包括代码类型预测、长文档QA、NLI、BABILong，未涉及多模态、长文档摘要、对话等更多长上下文场景。
- **合成数据质量**：合成QA对由多种LLM生成，可能存在噪声或偏差，未深入分析其影响。
- **持续预训练数据**：FineWeb-Edu来自网络文本，可能与下游领域分布差异较大；预训练长度仅8k（8段），对超长泛化的贡献机制需进一步理解。
- **基线对比公平性**：Mamba等模型参数多且预训练充分，而ARMT仅做少量持续预训练；另外未与RoPE扩展方法（如Position Interpolation）或FlashAttention等高效注意力实现对比。
- **理论分析不足**：联想记忆如何与Transformer内部表示交互仅做层重要性分析，缺乏可解释性研究。
- **计算资源消耗**：持续预训练仍需100小时8×H100，对于一般实验室门槛较高；微调48小时2×H100也需一定资源。
- **隐私假设**：小模型部署可减少数据泄露风险，但未量化隐私保护程度或与API模型的安全对比。
