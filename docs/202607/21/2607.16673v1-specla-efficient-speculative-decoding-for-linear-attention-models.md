## 摘要
线性注意力模型用循环状态取代了不断增长的KV缓存，但自回归解码仍然每次只读取、更新和写入一个状态。推测解码可以通过一次目标传递验证多个草稿令牌来降低这一成本，然而现有的推测系统是针对Transformer KV缓存设计的。对于有状态的线性注意力目标，验证必须遵循跨链和分支的循环依赖关系，接受必须仅更新被接受的状态轨迹，并且草稿者必须避免提交会浪费有状态验证工作的候选令牌。本文提出了SpecLA，一种针对有状态线性注意力模型的推测解码运行时。SpecLA使用拓扑感知内核验证链和树，存储验证过程中生成的紧凑因子以恢复被接受的状态，并使用置信度剪枝加上目标对齐的EAGLE风格草稿者，向验证器提供有用的候选令牌。在配备公共GDN-1.3B目标的NVIDIA H100上，SpecLA相比自回归解码实现了高达1.70倍的端到端加速。

## Abstract
Linear-attention models replace the growing KV cache with recurrent states, but autoregressive decoding still reads, updates, and writes these states one token at a time. Speculative decoding can reduce this cost by verifying several draft tokens in one target pass, yet existing speculative systems are designed for Transformer KV caches. For stateful linear-attention targets, verification must follow recurrent dependencies across chains and branches, acceptance must update only the accepted state trajectory, and the drafter must avoid submitting candidates that waste stateful verification work. This paper presents SpecLA, a speculative decoding runtime for stateful linear-attention models. SpecLA verifies chains and trees with topology-aware kernels, stores compact factors produced during verification to recover accepted states, and uses confidence pruning plus a target-aligned EAGLE-style drafter to feed useful candidates to the verifier. On an NVIDIA H100 with a public GDN-1.3B target, SpecLA achieves up to 1.70x end-to-end speedup over autoregressive decoding.

- **核心问题**：线性注意力模型使用循环状态（recurrent state）代替KV缓存，但自回归解码仍需逐token读取、更新和写入状态，导致内存带宽瓶颈。现有推测解码系统专为Transformer的KV缓存设计，无法高效处理线性注意力模型的循环依赖状态。
- **整体含义**：SpecLA是首个针对有状态线性注意力模型的高效推测解码运行时。它通过拓扑感知验证、紧凑因子状态管理和目标对齐草稿构建，将推测解码的加速优势扩展到线性注意力领域，在保持模型输出分布不变的前提下显著提升解码速度。

### 论文提出的方法论：核心思想、关键技术细节

1. **核心思想**：将推测解码的三阶段（草稿构建、目标验证、接受与状态提交）针对线性注意力模型的循环状态特性重新设计，重点解决验证核效率、接受状态恢复和草稿质量三个挑战。
2. **关键技术细节**：
   - **拓扑感知验证核**：
     - *状态驻留串行核*：按层优先顺序执行，对短链候选保持状态瓦片（V维分块）驻留SRAM，避免token间状态往返HBM。
     - *树掩码并行核*：将树依赖掩码插入GDN的UT分解中，直接并行验证所有候选节点，但设置开销较大。
     - *链分解混合核*：将草稿树分解为依赖链，每条链使用状态驻留串行核验证，就绪的链可并行执行，兼顾低开销与分支并行度。
   - **接受因子状态管理**：
     - *因子缓冲*：在验证过程中缓存每个候选token的紧凑因子（如投影key/value、衰减系数等），接受后仅对选中路径进行轻量级delta构造更新状态，避免全状态快照或token重放的高开销。
     - *延迟状态更新*：将接受因子的应用融合到下一次验证核中，消除独立的提交核，进一步降低状态往返开销。
   - **目标对齐草稿集成**：
     - *置信度引导剪枝*：基于路径累积对数概率，设置树阈值和token预算，提前修剪低概率分支，减少无效验证。
     - *EAGLE风格草稿层*：使用目标模型的循环特征训练草稿头，使剪枝分数反映目标动态，同时保持草稿层Transformer风格（短窗口内二次注意力开销可忽略）。

- SpecLA在混合数据集、GSM8K和HumanEval上分别实现1.42×、1.70×和1.06×端到端加速比（相对于自回归解码）。
