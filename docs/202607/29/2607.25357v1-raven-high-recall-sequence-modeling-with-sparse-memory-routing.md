## 摘要
长上下文召回在线性时间序列模型中凸显了它们在写入内存时的一种权衡。基于状态的状态空间模型（SSMs）和线性Transformer等模型采用密集写入方式，每到达一个新token就更新整个状态，这会导致干扰并使特定的过去token难以恢复。滑动窗口注意力（SWA）则表现出相反的行为：它通过存储显式token表示来稀疏写入，但仅限固定窗口内，因此一旦相关token被驱逐，召回率就会下降。介于这些模型之间，我们引入了Raven，一种线性时间序列模型，它维护一组固定的内存槽位，并在每一步通过学习的、依赖于输入的路径仅衰减和更新选中的子集。这使得Raven能够缓解SWA基于位置的覆盖和硬驱逐问题，同时减少SSMs中密集状态更新的干扰，从而更有效地保留长距离内容。在召回密集的基准测试中，Raven与之前的线性时间基线模型相比具有竞争力或更优，在SWA和SSMs均严重退化的长上下文召回任务上表现强劲。当外推到训练长度16倍的上下文长度时，它仍然有效，并在混合架构中获得了类似的提升。

## Abstract
Long-context recall in linear-time sequence models highlights a tradeoff in how they write to memory. State-based linear models, such as state-space models (SSMs) and linear Transformers, write densely, updating the entire state for each newly arrived token, which leads to interference and makes specific past tokens hard to recover. Sliding-window attention (SWA) exhibits the opposite behavior: it writes sparsely by storing explicit token representations, but only within a fixed window, so recall drops once the relevant token is evicted. Interpolating between these models, we introduce Raven, a linear-time sequence model that maintains a fixed set of memory slots and, at each step, decays and updates only a selected subset via learned, input-dependent routing. This lets Raven mitigate SWA's position-based overwriting and hard eviction while reducing interference from dense state updates in SSMs, thereby preserving long-range content much more effectively. Across recall-intensive benchmarks, Raven is competitive with or outperforms prior linear-time baselines, achieving strong long-context recall where both SWA and SSMs sharply degrade. It remains effective when extrapolating to context lengths as large as 16x its training length, with similar gains in hybrid architectures.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究动机**：线性时间序列模型（如状态空间模型 SSMs 和线性 Transformer）在长上下文召回任务中存在根本性权衡：它们写入记忆的方式不同。SSMs 采用**密集写入**——每到达一个新 token 就更新整个状态，导致存储信息相互干扰，难以精确恢复特定 token；而滑动窗口注意力（SWA）采用**稀疏写入**——仅在固定窗口内保留显式 token 表示，窗口满后最早的 token 被硬驱逐，导致长距离召回下降。两种模型各自牺牲了召回性能的一个维度。
- **核心问题**：如何设计一种线性时间序列模型，既能像 SWA 一样稀疏写入以降低干扰，又不会因位置驱动（而非内容驱动）的硬驱逐而丢失信息？同时要避免 SSMs 的密集更新带来的过度覆盖。
- **整体含义**：论文认为“写入何处”与“保留多久”是正交的设计轴，现有模型未解耦。通过显式区分路由（决定写入哪个记忆槽）和遗忘（决定写入选中的槽后如何衰减），可以显著提升长上下文的召回能力，且保持线性复杂度。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想：路由槽记忆（Routing Slot Memories, RSMs）与 Raven 实例化

- 提出 RSMs 统一框架：固定 M 个记忆槽，每个槽独立更新。更新由**路由向量**控制，决定当前 token 的信息写入哪些槽、写入强度多大。SSMs 对应于全 1 路由（密集写入），SWA 对应于 one-hot 时序路由（稀疏但基于位置），而 **Raven** 使用**稀疏、输入依赖的路由**，并结合显式衰减。
- **Raven 具体设计**：
  1. **双状态结构**：维护独立的键状态 Sᵏₜ 和值状态 Sᵛₜ（均为 M×d 矩阵），读取出使用 softmax 注意力（类似 SWA）。
  2. **路由生成**：给定输入 xₜ，先通过线性层得分数 mₜ = σ(W xₜ) ∈ ℝᴹ，然后取 Top-K 保留，其余置零，再归一化：`gₜ = KeepTopK(mₜ)`，`rₜ = gₜ / α∑gₜ[i]`。K 控制稀疏度（默认 K=32, M=256）。路由依赖输入，且只激活 K 个槽。
  3. **遗忘（衰减）**：对选中的槽施加衰减 `aₜ = -SoftPlus(wᵀxₜ)·exp(Δ)`（类似于 Mamba-2 的输入依赖标量衰减），未选中的槽（rₜ[i]=0）完全不衰减，内容冻结。
  4. **更新公式**：
     ```
     Sᵏₜ = exp(aₜ rₜ) ⊙ Sᵏₜ₋₁ + (1 - exp(aₜ rₜ)) kₜᵀ
     Sᵛₜ = exp(aₜ rₜ) ⊙ Sᵛₜ₋₁ + (1 - exp(aₜ rₜ)) vₜᵀ
     oₜ = (Sᵛₜ)ᵀ softmax(Sᵏₜ qₜ)
     ```
     当 rₜ[i]≈0 时，exp(aₜ rₜ[i])≈1，槽内容几乎不变；当 rₜ[i] 大时，大幅衰减并覆盖。
  5. **无需短卷积**：与其他 SSMs 不同，Raven 省略了 QKV 上的短卷积，简化了架构。
  6. **训练效率**：利用双 pass 的 GLA（门控线性注意）核实现，将 Raven 分解为两次 GLA 运算，可高效并行训练。

## 7. 优点
