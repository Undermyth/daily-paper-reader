## 摘要
Transformer的深度并非均匀使用：较低和中间的层构建语义表示，而较高的层则逐渐将其专门化以用于预测。我们将这种分工转化为CoMem（理解记忆），它仅通过中间层写入每个上下文块，检索固定数量的缓存残差状态，并在生成的打包结果上重新计算查询条件下的上层。对于固定的检索预算，模型侧的读取计算和内存与存储的上下文长度无关。我们在统一的无需聊天模板的协议下评估了持续训练的Qwen3-8B基础语言模型。骨干网络被冻结；旗舰版本仅在普通PG19上训练秩为32的自蒸馏LoRA，我们另外报告了无适配器分支的结果。CoMem在RULER上达到97.05，在LoCoMo上达到38.27，而全上下文KV-Direct为34.59；对话记忆优势在对话聚类重采样和独立评判下依然存在。在额外的长上下文和长文档任务上的结果既展示了有界检索的优势，也暴露了其窗口内压缩代价。受控的深度扫描表明，更深的缓存降低了每次查询的重计算，但引入了保真度损失，而自蒸馏大幅修复了该损失。在NVIDIA H20上的单独无适配器效率对照中，128k下CoMem使用18.26 GB而非89.36 GB，并实现了7.83倍的预填充加速。这些结果表明，长上下文记忆可以沿层轴组织，而不仅仅是沿标记轴。

## Abstract
Transformer depth is not used uniformly: lower and middle layers build semantic representations, while upper layers increasingly specialize them for prediction. We turn this division of labor into CoMem (Comprehension Memory), which writes each context chunk only through an intermediate layer, retrieves a fixed number of cached residual states, and recomputes the query-conditioned upper layers over the resulting pack. For a fixed retrieval budget, model-side read compute and memory are independent of stored-context length. We evaluate a continued-trained Qwen3-8B base LM under a unified chat-template-free protocol. The backbone is frozen; the flagship trains only a rank-32 self-distillation LoRA on plain PG19, and we report an adapter-free arm separately. CoMem reaches 97.05 on RULER and 38.27 on LoCoMo versus 34.59 for full-context KV-Direct; the dialogue-memory advantage survives conversation-cluster resampling and an independent judge. Results on additional long-context and long-document tasks expose both the benefits of bounded retrieval and its in-window compression tax. Controlled depth sweeps show that deeper caching lowers per-query recomputation but incurs a fidelity loss that self-distillation substantially repairs. In a separate adapter-free efficiency control on an NVIDIA H20 at 128k, CoMem uses 18.26 GB rather than 89.36 GB and achieves a 7.83x prefill speedup. These results show that long-context memory can be organized along the layer axis, not only the token axis.

## 1. 核心问题与整体含义

- **研究背景**：长上下文语言建模面临两大固有瓶颈：自注意力的二次方预填充成本，以及 KV 缓存随上下文长度线性增长的内存开销。同时，模型还受限于预训练时的位置编码范围（如 Qwen3-8B 原生窗口为 40,960 token，宣称的 131,072 限制依赖未激活的 YaRN 扩展）。
- **核心洞察**：Transformer 的各层并非同等使用——低层和中层即可获得语义信息，上层则越来越特化为当前查询和预测服务。作者将这一深度分工视为一种可测量的"复用轴"，认为长上下文记忆不仅可以沿 token 轴组织，还可以沿 layer（深度）轴组织。
- **总体含义**：提出 CoMem（Comprehension Memory），通过"浅层写、深层读"的方式，使模型侧的读取计算和内存占用在固定检索预算下与存储的上下文总长度无关，为无界上下文记忆提供了新的范式。

## 2. 方法论

**核心思想**：将 Transformer 按深度切分。写阶段只需运行浅层，把中间层的残差张量作为缓存；读阶段只对检索到的有限个块重新计算上层，从而解耦"存储成本"与"在线读取成本"。

**主要技术细节**：

- **写入（Write）**：文档按互不重叠的 512-token 块流式处理，每块从位置 0 重新开始 RoPE，仅经过第 0 至第 j 层，将每个 token 的残差张量 h_j 存入外部存储（通过文本索引）。
- **选择（Select）**：使用迭代 BM25 检索与查询最相关的 top-k 个块（旗舰配置 k=12、hop width 4、自动三轮扩展去重）。
- **读取（Read）**：将 [BOS 标记；选中的 h_j；查询对应的 h_j] 打包，重新赋予连续的 RoPE，然后对第 j 至 L 层进行完整的前向计算，包含跨块的完整因果注意力。
- **深度切分（split depth j）**：作为质量-成本旋钮——j=0 时等价于选择性全量前向；j 越深，写入工作量越大但每次查询的重计算量越小，同时查询无关的缓存状态可读性下降。
- **自蒸馏**：以冻结的 j=0 模型为教师，在教师 top-64 logit 支持上训练秩为 32 的 LoRA（α=64，只作用于第 12–35 层），目标为双向 KL：L = 0.6·KL(p‖q) + 0.4·KL(q‖p)，无交叉熵辅助项。骨干网络保持冻结，训练数据为普通 PG-19 文本（无检索、无任务监督）。

**关键公式**：

- 存储开销：存储 h_j 的每 token 字节数相对于全量 bf16 KV 为 d / (2L·d_kv) = n_q / (2L·n_kv)，在 Qwen3-8B 上为 1/18（8KB vs. 144KB per token）。
- 读取长度固定：|pack| = sink + k·c + query ≈ 6.7k tokens，与存储上下文长度无关。

## 3. 实验设计

**数据与基准**（统一使用无聊天模板的纯文本协议）：

- RULER（合成长上下文检索：单针、多键、变量追踪，8k–128k）
- LongEval（行检索）
- LongBench（6 个 QA 数据集的 token F1）
- BABILong（qa1/qa2/qa5 推理任务，0k–32k）
- LoCoMo（长对话记忆，1,986 个问答对）
- 另在 Qwen3 全系列（0.6B 至 32B）和 Qwen3-30B-A3B、Tencent Hunyuan Hy3（80 层 MoE）上做了泛化性验证。

**对比方法**：

- KV-Direct（全上下文、残差流重建 KV 的参考方法）
- StreamingLLM、InfLLM、HCache-style、MemoryLLM（后两者为额外参考，MemoryLLM 使用非骨干的 Llama-3-8B-chat 检查点）
- CoMem 的两个版本：蒸馏旗舰（j=12 + LoRA）与冻结无适配器版本

**核心结果**：

- RULER 97.05 vs. KV-Direct 78.80；LongEval 69.0 vs. 65.2；LongBench 12.15 vs. 12.17（基本持平）；BABILong 3-task 均值 50.43 vs. 63.00（低于全上下文基线，暴露压缩代价）；LoCoMo 38.27 vs. 34.59（+4.81 点，bootstrap 95% CI [2.34, 7.27]）。
- 效率：H20 上 128k 上下文时，CoMem 峰值内存 18.26 GB vs. 全上下文 89.36 GB，全写入包含预填充加速 7.83×；解码速度与 Dense 相当（128k 时 1.07×）。
- 消融表明：检索贡献独立于深度复用（j=0 检索即达 41.59 LoCoMo）；自蒸馏在相同 j=12 恢复 13.75 LoCoMo 点；跨块注意力比块对角显著更好；更宽检索不一定更好。

## 6. 主要结论与发现

- 深度分工是真实且可度量的：语义内容深度近似尺度不变（约 0.45L），而零样本可读深度随模型规模加深。
- 长上下文记忆可以沿层轴组织：固定检索预算下，模型侧读取时间和内存与存储上下文长度无关。
- CoMem 在长范围检索（RULER）和长对话记忆（LoCoMo）上显著优于未扩展的全上下文 KV-Direct；在窗口内推理任务（BABILong qa1/qa2）上付出了压缩代价，并非全面优于全上下文。
- 自蒸馏 LoRA 是有效的"界面修复"：仅用 PG-19 普通文本训练即可大幅恢复深层缓存的可读性，且该效果可迁移到 HCache 路径和 MoE 骨干。
- 深度不是免费的精度增益，而是一个质量-计算权衡旋钮。

## 7. 优点

- **视角新颖**：将长上下文问题从"token 轴"扩展到"层轴"，提出深度作为可度量的复用维度。
- **方法简洁且可部署**：骨干冻结、仅需一个轻量 LoRA、外部存储线性、读取有界，工程实现清晰（提供伪代码）。
- **实验设计系统**：动机探针（线性探针、因果截断）、机制消融（检索 vs. 深度复用 vs. 自蒸馏）与端到端基准相互印证。
- **统计严谨性较好**：对 LoCoMo 采用 item bootstrap、cluster bootstrap 与独立第三方评判三重验证，并对超窗口结果和异骨干基线做了诚实声明。
- **泛化验证**：跨模型规模（0.6B–32B）与稀疏 MoE（Qwen3-30B-A3B、Hunyuan Hy3）均有效，而非单一模型上的巧合。
- **公开复现意识**：提供匿名代码仓库、配置存档、评估脚本与计算声明。

## 8. 不足与局限

- **任务覆盖偏窄**：仅英语、以检索式 QA 为主；未覆盖长文本生成、代码、多语言、多模态记忆。
- **窗口内压缩代价明确存在**：BABILong qa1/qa2 明显弱于全上下文 KV-Direct，说明有界读取并非普遍优于全上下文。
- **检索器限制**：仅使用 BM25 词法检索，对表层形式差异大的语义匹配可能失效；未测自然多跳工作负载下的检索延迟。
- **LoCoMo 对话簇太少**（仅 10 簇），尽管做了聚类 bootstrap，仍不能替代更多真实对话的验证。
- **消融统计强度不足**：部分实验为单一点估计、无多 seed；chunk size 与注意力对比未做显著性检验。
- **无位置扩展对照**：超过 40,960 token 的结果均为未扩展的应激参考，未与 YaRN 扩展的全上下文模型比较，不能宣称对长度扩展模型的最优性。
