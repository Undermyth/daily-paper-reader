## 摘要
Top-$K$ 稀疏注意力通过仅关注键值（KV）条目的一小部分子集来降低 Softmax 和值聚合的成本。然而，识别该子集仍然需要对完整 KV 缓存中的当前查询进行评分，并执行全局 Top-$K$ 选择，这使得选择器的成本随上下文长度线性增长，并限制了稀疏注意力在长上下文解码中的实际效率。本文介绍了 ReTopK，一种无需训练的方法，通过复用历史检索决策来加速动态 Top-$K$ 注意力。ReTopK 基于以下观察：相似的查询通常会关注重叠的支持集，且部分重叠的支持集仍能保留大部分精确 Top-$K$ 注意力质量。对于每个注意力头，它维护一个有界的查询-支持对历史缓存，为每个新查询检索最相似的缓存查询，将其存储的支持集与近期窗口取并集，然后仅使用精确的当前查询分数对生成的紧凑候选集进行重新排序。当复用不可靠时，基于相似度的回退机制会调用完整历史的精确 Top-$K$，而周期性精确刷新限制了缓存漂移。ReTopK 保留完整的 KV 缓存，仅复用选中的索引，而非历史分数、注意力权重或输出。在 16K--128K 上下文长度下，ReTopK 在所评估的近似方法中实现了最低的 PG19 困惑度和最高的 NIAH 与 LongBench 分数。在 128K 上下文且 $K=512$ 时，ReTopK 相对于精确 Top-$K$ 仅增加 0.50\% 的困惑度，同时将注意力计算加速了 $3.07\times$。

## Abstract
Top-$K$ sparse attention reduces the cost of Softmax and value aggregation by attending to only a small subset of key--value (KV) entries. However, identifying this subset still requires scoring the current query against the full KV cache and performing global Top-$K$ selection, leaving selector cost linear in context length and limiting the practical efficiency of sparse attention for long-context decoding. In this paper, we introduce ReTopK, a training-free method that accelerates dynamic Top-$K$ attention by reusing historical retrieval decisions. ReTopK builds on the observation that similar queries often attend to overlapping supports and that partially overlapping supports can still preserve most of the Exact Top-$K$ attention mass. For each attention head, it maintains a bounded cache of historical query--support pairs, retrieves the most similar cached queries for each new query, unions their stored supports with a recent window, and reranks only the resulting compact candidate set using exact current-query scores. A similarity-based fallback invokes full-history Exact Top-$K$ when reuse is unreliable, while periodic exact refreshes limit cache drift. ReTopK retains the complete KV cache and reuses only selected indices, rather than historical scores, attention weights, or outputs. Across 16K--128K contexts, ReTopK achieves the lowest PG19 perplexity and the highest NIAH and LongBench scores among the evaluated approximate methods. At 128K with $K=512$, ReTopK incurs only a 0.50\% perplexity increase over Exact Top-$K$ while accelerating attention computation by $3.07\times$.

## 1. 核心问题与研究动机

- **背景**：大语言模型（LLM）在长文档、代码库和长交互历史等场景中，自回归解码的注意力成本随 KV 缓存长度线性增长。虽然 FlashAttention 等 IO 感知内核提升了硬件效率，但并未消除解码注意力对上下文长度的线性依赖。
- **核心问题**：Exact Top-K 稀疏注意力虽然能将 Softmax 和值聚合限制在 K 个最高分条目上，但**选择这 K 个条目本身仍需对全部 KV 缓存计算查询-键（QK）分数并执行全局 Top-K 选择**。因此，它稀疏化了聚合步骤，却没有稀疏化索引发现步骤——选择器成本随上下文长度线性增长，成为长上下文解码的关键瓶颈（如图 1 所示，全历史 QK 打分与 Top-K 选择在长上下文下占据 Exact Top-K 注意力延迟的 87%–97%）。
- **设计问题**：能否让动态选择器在不逐解码步搜索全历史的情况下恢复查询特定的注意力支持集？

## 2. 方法论：ReTopK

### 2.1 核心思想
- **核心观察**：相似查询往往产生重叠的 Top-K 支持集；即便支持集仅有部分重叠，也能保留大部分精确 Top-K 注意力质量。
- 历史查询-支持对构成检索决定的紧凑记录，新查询可先"召回"相似历史查询的支持集，再仅对其并集进行精确重排，从而避免全历史搜索。
- **设计三原则**：
  1. 检索决定应与其原始查询一同存储，用查询相似度作为轻量检索信号；
  2. 召回的支持集仅作为候选，必须用当前查询精确重排；
  3. 复用必须配备低置信度和陈旧检索的兜底机制。

### 2.2 技术流程
ReTopK 采用"召回-再排序"（Recall-Before-Rerank）流程，按注意力头独立维护一个容量为 C 的 FIFO 查询-支持缓存（缓存归一化查询向量与对应选中索引）。对每个新查询：

1. **相似度召回**：计算当前归一化查询与所有缓存查询的余弦相似度，取 Top-R 个最相似的缓存条目（只需与 C 个缓存查询比较，而非全部 Lt 个键）。
2. **候选集构建**：将 R 个召回条目的支持集与一个大小为 W 的近期窗口取并集，得到紧凑候选集 At，大小 Mt ≤ RK + W ≪ Lt。
3. **精确重排**：仅对候选集中的键计算精确当前查询 QK 分数，从中选择 Top-K 作为最终支持集。
4. **稀疏注意力**：对重排后的支持集执行 Softmax-值聚合。

### 2.3 可靠性机制
- **相似度回退**：当最大缓存查询相似度 ρ_max < τ 时，回退到全历史 Exact Top-K 路径。
- **周期刷新**：每 Tr 步执行一次精确 Top-K，限制在线缓存的长期漂移。
- 两条机制互补：回退处理无可靠匹配的查询，刷新限制长期误差累积。

### 2.4 重要性质
- **只复用索引**：不复用历史 QK 分数、注意力权重或输出；所有分数、归一化权重和值聚合均基于当前查询和原始 KV 缓存精确计算。
- **保留完整 KV 缓存**：不驱逐任何键值条目，支持查询相关的全历史检索。
- **复杂度优势**：Reuse 步的选择器工作量（C 缓存匹配 + Mt 候选打分）与上下文长度无关；额外元数据开销为 O(Cd + CK) 每头。
- **GPU 实现**：三段式融合内核（融合选择器、索引 QK、融合 Top-K 选择 + Softmax-值聚合 + 缓存更新），配合持久化工作空间。

## 6. 主要结论与发现

- **质量-效率权衡**：在 16K–128K 上下文中，ReTopK 的两种设置（τ=0.85 与 τ=0.90）在 PG19 困惑度上排名近似方法第一、第二，并在 NIAH 和 LongBench 上取得最佳的近似方法结果。
- **关键数字**：128K 上下文、K=512 时，ReTopK（τ=0.85）比 Exact Top-K 仅增 0.50% 困惑度，注意力计算加速 3.07×；质量导向的 τ=0.90 保持 1.14–2.25× 加速，并在各长度下领先所有近似方法。
- **跨模型泛化**：无需模型特定调参，ReTopK 在 Llama-3.1-8B 和 Qwen2.5-14B 上实现 82.5%–89.6% 复用率、−0.46% 至 +2.76% 困惑度变化、1.26–2.66× 加速。
- **保真度**：虽仅 56.9% 的支持召回率，但保留 91.6% 注意力质量和 97.2% 头输出余弦相似度——错配索引的注意力权重很低，不损害输出质量。
- **端到端扩展性**：随上下文从 128K 增至 5M，端到端加速从 1.13× 提升至 3.73×，因为共享解码器开销占比下降，注意力节约愈发显著。
- **长程稳定性**：8K 续写下 ΔPPL 保持在 2.08% 以内，且无后期误差激增。

## 7. 优点

- **训练免费、即插即用**：无需任何训练或微调，可直接替换现有 Exact Top-K 注意力。
- **思想简洁有力**："先召回再排序"直观且有效，基于相似查询支持集重叠的实证观察，而非直觉猜测。

## 8. 不足与局限

- **近似方法的固有偏差**：虽然质量损失小，但保真度分析显示支持召回率仅 56.9%——在某些对精确索引敏感的下游任务（如精确信息定位场景）可能存在风险。
- **对照基线配置可争议性**：Loki 等方法的对比配置（K=512、r=64）可能低于其最优工作点，削弱了对比公平性；StreamingLLM 作为固定窗口基线，其极低 NIAH 分数是方法设计使然，作为对照的信息量有限。
