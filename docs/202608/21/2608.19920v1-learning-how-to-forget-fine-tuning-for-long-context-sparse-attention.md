## 摘要
许多先前的工作通过稀疏注意力解决键值（KV）缓存选择和压缩问题，以便在不过度消耗硬件预算的情况下实现 Transformer 语言模型的长上下文推理。我们提出了一种使用稀疏注意力对模型进行微调的新方法。该方法适用于任何 KV 缓存策略，可在适中的硬件预算（例如，单个配备 40 GB RAM 的 Nvidia A100 GPU）上运行，并允许模型与策略共同自适应，其性能通常优于使用精确注意力（序列并行）训练的模型。我们还提供了 H2O 稀疏注意力（我们实验中的领先策略）的高效实现，并支持专门的缩放点积注意力内核。KeysAndValues（https://github.com/awslabs/keys_values），一个新的用于长上下文推理和微调的开源库，为本文讨论的所有方法提供了易于使用且高性能的代码。

## Abstract
A lot of prior work addressed key-value (KV) cache selection and compression by sparse attention to enable long-context inference for transformer language models without excessive hardware budgets. We provide a new method for fine-tuning models with sparse attention. It works for any KV cache policy, runs on a moderate hardware budget (e.g., a single Nvidia A100 GPU with 40 GB RAM), and allows the model to co-adapt with the policy, often outperforming models trained with exact attention (sequence parallelism). We also provide an efficient implementation of H2O sparse attention (the leading policy in our experiments) with dedicated scaled dot product attention kernel support. KeysAndValues (https://github.com/awslabs/keys_values), a new open source library for long-context inference and fine-tuning, provides easy-to-use and performant code for all methods discussed here.

### 1. 论文的核心问题与整体含义
- **研究动机**：现代大语言模型（LLM）需要处理超长上下文（如 64k、128k tokens），但精确注意力（Exact Attention）的 KV 缓存会随序列长度线性增长，导致显存爆炸。稀疏注意力（Sparse Attention）通过固定大小的 KV 缓存和逐出（Eviction）策略来解决这一问题，但现有方法与模型训练是**脱节**的：模型通常使用精确注意力（序列并行）训练，推理时才替换为稀疏注意力，导致模型从未见过被压缩后的注意力模式，性能严重下降。
- **核心问题**：本文回答了一个关键问题——**如何让模型在推理时使用稀疏注意力，同时让模型在训练阶段就与特定的 KV 缓存策略“共同适应”（co-adapt）**，从而显著提升稀疏注意力推理的性能？
- **整体含义**：本文提出了一种新的微调范式，它不修改模型架构、不依赖特定的注意力核，而是**在训练时将 KV 缓存策略直接“嵌入”前向传播过程**，使模型学会在该策略的信息丢失模式下仍然保持性能。该方法的硬件需求极低（单张 A100 40GB 即可运行梯度计算），极大地降低了长上下文微调的门槛。

### 2. 论文提出的方法论（核心技术细节）
- **总体思路**：不是设计新的稀疏注意力模式，而是提供一种**通用的、策略无关的微调方法**。核心思想是：在正向传播时，对每个 chunk 执行真正的稀疏注意力（按 KV 缓存策略逐出信息），并通过**重放日志（Replay Log）**记录所有决策；在反向传播时，利用**重放缓存（Replay Caches）**重放这些决策，从而计算梯度。
- **三大关键技术**：
  - **嵌套激活检查点（Nested Activation Checkpointing）**：针对长上下文，将序列划分为多个“小组”（Cells，即 chunk 的组）。外层循环遍历层（Layers），内层循环遍历每个 Cell。每个 Cell 内部的 SDPA 调用作为独立的 autograd 单元，避免整个长序列的计算图常驻 GPU，从而将 GPU 显存占用降至 KV 缓存大小级别。
  - **KV 缓存缓冲区的线性递推与增量编码（Delta Encoding）**：利用相邻 chunk 的 KV 缓存缓冲区仅相差 `S*D` 个值（S 为 chunk 大小）这一特点，通过 `scatter` 和 `gather` 操作实现线性递推 `keys' = scatter(keys, index, key_new)`。在 autograd 图中，只存储**增量** `delta_key` 和 `delta_value`，而不是完整的 `keys`/`values`，从而将在反向传播中的 KV 缓存显存需求降低约 k 倍（k 为每 Cell 的 chunk 数）。
  - **PyTorch Autograd Saved Tensors Hooks 的非选择性利用**：通过 `pack_hook`/`unpack_hook` 机制，配合**注解列表（Annotation List）**，识别 KV 缓存缓冲区节点，将其替换为增量编码。该方法使梯度计算对 KV 缓存策略**完全无关（agnostic）**，无需为每种策略编写专用的 CUDA 内核。
- **对 H2O 策略的改进**：
  - **逐批次选择**：原版 H2O 对同一头部的所有批次使用相同的逐出索引，本文实现了逐批次（batch-independent）选择。
  - **归一化 H2O 分数**：为消除“缓存存在时间越长、得分越高”的偏差，引入了除以缓存驻留时间的归一化分数。
  - **高效内核**：提供了 Triton 代码，可以在 FlashInfer SDPA 内核执行的同时返回注意力权重之和，避免了原生 H2O 使用 naive SDPA 的低效问题。

### 3. 实验设计（数据集、Benchmark、对比方法）
- **基准数据集 (Benchmark)**：基于 **Helmet**[69] 长上下文基准测试，涵盖 64k 和 128k 两种上下文长度，共 10 个任务，覆盖 5 类能力：
  - **RAG 问答**：NQ、TriviaQA、PopQA、HotpotQA（使用 SubEM 指标）。
  - **少样本上下文学习**：TREC Coarse、SNIPS NLU、CLINC150（使用 Accuracy 指标）。
  - **长文档问答**：InfiniteBench QA（ROUGE-F1）、InfiniteBench MC（Accuracy）。
  - **合成检索**：JSON-KV（SubEM）。
- **对比方法**：
  - **`us`（本文方法）**：使用论文提出的嵌套检查点 + 稀疏注意力微调。
  - **`sp`（序列并行）**：使用 MS-SWIFT 库 + DeepSpeed ZeRO-3 进行微调，这是 SOTA 的长上下文精确注意力训练方式。
  - **`no`（无微调基线）**：使用基础模型 Qwen3-4B-Instruct-2507。
- **缓存策略**：`lastrec` (lr)、`smart lastrec` (slr)、`h2o` (h2o)、`h2o_norm` (h2o_no)、`h2o_orig` (h2o_or，原版逐批次全局选择)。块大小 (Chunk Size) 包括 2048 和 1024。
- **评估设置**：按验证损失选择最佳检查点，在测试集上评估。模型使用 LoRA 微调（rank=16, α=16）。

### 7. 优点（亮点）
- **方法先进性与通用性**：将 KV 缓存策略作为训练过程中的一等公民，适用于**任意**策略（H2O、lastrec 或自定义逻辑），无需为每种策略编写复杂的内核（与 OOMB 相比）。
