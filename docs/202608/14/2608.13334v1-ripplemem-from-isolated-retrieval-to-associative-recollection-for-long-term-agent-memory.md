## 摘要
基于LLM的智能体越来越依赖外部记忆来支持长时推理和交互。然而，主要瓶颈不在于简单地存储过往经验，而在于当相关信息分布在多次交互中时，如何恢复正确的证据集。现有方法难以应对这一访问问题。全上下文方法需要嘈杂的长上下文搜索，平面检索通常返回孤立且不完整的记录，而基于图的记忆系统在压缩丰富事件上下文的同时，构建成本可能很高。我们提出RippleMem，一种用自适应联想回忆替代一次性检索的长期记忆系统。受线索依赖的情境回忆和联想补全启发，RippleMem将交互历史存储为富含线索的情境记忆单元，并组织在事件为中心的记忆图中。对于给定查询，它首先通过混合线索回忆相关记忆锚点，然后沿语义和结构关联从这些锚点扩展，以恢复缺失的支持性证据。这样，最初回忆的记忆不仅作为答案上下文，还作为补全回答问题所需证据的线索。在LoCoMo和LongMemEval-S上的实验表明，RippleMem在评估设置中取得了最佳整体性能，在LoCoMo上将LLM-as-a-Judge准确率提高了3.95%，在LongMemEval-S上提高了高达11.87%，同时将图构建成本降低了约30倍。

## Abstract
LLM-based agents increasingly rely on external memory to support long-horizon reasoning and interaction. However, the main bottleneck is not simply storing past experience, but recovering the right set of evidence when relevant information is distributed across many interactions. Existing approaches struggle with this access problem. Full-context methods require noisy long-context search, flat retrieval often returns isolated and incomplete records, and graph-based memory systems can be expensive to construct while compressing rich event context. We introduce RippleMem, a long-term memory system that replaces one-shot retrieval with adaptive associative recollection. Inspired by cue-dependent episodic retrieval and associative completion, RippleMem stores interaction history as cue-rich episodic memory units and organizes them in an event-centric memory graph. Given a query, it first recalls relevant memory anchors through hybrid cues, then expands from these anchors along semantic and structural associations to recover missing supporting evidence. In this way, initially recalled memories serve not only as answer context, but also as cues for completing the evidence needed to answer. Experiments on LoCoMo and LongMemEval-S show that RippleMem achieves the best overall performance across evaluated settings, improving LLM-as-a-Judge accuracy by 3.95% on LoCoMo and up to 11.87% on LongMemEval-S, while reducing graph construction cost by about 30x.

**核心贡献（一句话）：** 论文将长期记忆访问从"一次性检索"转向"证据条件化的联想回忆"——先召回记忆锚点，再以锚点为线索沿关联路径补全缺失证据，使记忆不仅提供答案上下文，还充当继续回忆的线索。

### 二、论文提出的方法论

**核心思想：**
- 借鉴认知科学中的**线索依赖的情境回忆**和**联想补全**理论，将交互历史组织为事件中心的记忆空间。
- 采用"写入—读取"两阶段设计：写入阶段构建富含线索的情境记忆单元并建立事件中心图；读取阶段进行自适应联想回忆以补全证据。

#### 1. 写入阶段（Write Phase）

**（1）富含线索的情境记忆构建（Cue-Rich Episodic Memory Construction）**
- 将对话历史按连续轮次窗口（含局部重叠）切分，交给模式引导的LLM抽取器。
- 抽取的记忆单元遵循固定模式：

  `mi = (ri, vi, Pi, Li, Ti)`

  - `ri`：规范化的事件重述，可独立于原对话理解；
  - `vi`：ri 的稠密向量表示；
  - `Pi`：参与者；
  - `Li`：地点；
  - `Ti`：时间线索或区间。
- 关键设计：强制消解代词、锚定相对时间、将多事件窗口拆分为独立单元；无法确定的信息留空而非推断。

**（2）事件中心记忆图（Event-Centric Memory Graph）**
- 将记忆单元构成稀疏带权图 `G = (M, E)`，边分为两类：
  - **语义关联**：`ssem(i,j) = cos(vi, vj)`，捕获记忆重述间的意义邻近度；
  - **结构关联**：基于参与者（Jaccard重叠）、地点（Jaccard重叠）、时间（重叠或指数衰减）计算：

  `uTij = 1（若区间重叠），否则 exp(−Δ(Ti,Tj)/τ)`

  加权聚合得到 `sstr(i,j)`。
- 稀疏增量构图：新单元插入时，从语义近邻和基于线索的索引获取候选池，对超过阈值的候选保留语义边和结构边，每节点各限 `Ksem` / `Kstr` 条。

#### 2. 读取阶段（Read Phase）

**（3）自适应联想回忆（Adaptive Associative Recollection）**
- **混合初始回忆**：从查询中提取语义、词法和结构化线索，进行三种互补召回：

  `C0 = Csem ∪ Clex ∪ Ccue`
- **记忆锚点规划**：通过模式约束的回忆控制器 `Πrec` 输出：是否继续（dr）、选定的锚点（Ar）、缺失支持目标（gr）；
- **锚点局部扩展**：从选定锚点出发，在图的有界邻域内（h跳）沿语义和结构两种边分别扩展，候选按缺失支持目标打分，两通道结果按记忆身份合并形成支持集 `Sr`，更新证据状态 `C ← C ∪ Sr`；循环直到证据充分、无新支持或达到预算。

**（4）证据组织（Evidence Assembly）**
- 按记忆身份去重合并后，用确定性的源感知排序：

  `ρ(m) = λq·a(q,m) + λp·π(m) + λa·Ianc(m)`

- 取Top-K记忆构成最终证据上下文，交给LLM生成答案。

### 六、论文的主要结论与发现

1. **RippleMem在双基准上均取得最佳综合性能**：
   - LoCoMo：52.49% F1、44.05% BLEU-1、87.14% judge准确率；相对提升F1 3.98%、BLEU-1 3.62%（对SimpleMem）、judge准确率3.95%（对RF-Mem）；
   - LongMemEval-S：SimpleMem设置下84.80%、EverMemOS设置下86.60%，均为组内最优；
   - EverMemBench：54.75%总准确率，相对MemOS提升28.13%。

2. **在证据分布式问题上收益更显著**：
   - LoCoMo时间推理：F1提升5.45点、judge准确率提升9.66点；
   - LongMemEval-S多会话推理：78.20 vs. SimpleMem的60.92；80.45 vs. EverMemOS的73.68；
   - 这验证了"从锚点扩展以补全缺失证据"的核心设计。

3. **受控比较证实联想回忆的独特价值**：
   - 在同等记忆单元和证据预算下，RippleMem优于RF-Mem，说明增益不仅来自联想检索的风味，更来自**将已召回证据作为进一步补全的线索**这一具体机制；
   - 消融显示：去除图扩展导致最大下降（87.14→83.12），证明一阶召回确实会遗漏关键支持证据。

4. **效率优势显著**：
   - 构建时间和token比Mem0_g、Zep降低约30×和48.7–69.3×；
   - 答案上下文紧凑（1,471.93 tokens/问题）且准确性最高；
   - 边构建用类型化评分替代LLM判定，在准确率更高的情况下节省约27.7×构建token。

5. **对抗性问题上具备保守验证能力**：
   - 对无支持问题，RippleMem通过追加一轮有界验证，正确识别证据不足而非强行作答（86.32% judge准确率）。
