## 摘要
Transformer之所以具有强大的长上下文检索能力，很大程度上归功于其随上下文长度增长的token级记忆。然而，这种灵活性在训练过程中会产生二次方的计算复杂度，并在自回归推理过程中导致键值缓存线性增长。循环神经网络的替代方案通过将整个历史压缩为固定大小的状态来实现高效解码，但在召回密集型任务上通常表现不佳，因为早期的关联通常会被后续更新覆盖，只保留最近的上下文信息。在本文中，我们提出了跨上下文历史记忆锚点路由（MARCH），这是一种网络架构，能够有效地将状态空间模型扩展到固定大小维度之外，同时在长序列上保持计算效率。MARCH周期性地将累积的循环状态检查点缓存为状态锚点，并将每个锚点与紧凑的、内容条件的锚点键关联。这使得MARCH能够维护一个记忆库，随着上下文长度的增加而增长，从而在历史分辨率和记忆成本之间提供可控的权衡。在每个token处，MARCH生成一个锚点查询，以关注所有因果可用的状态锚点，输出则通过当前状态对所有历史锚点进行注意力式聚合来计算。我们表明，在标准预训练之后，MARCH在常识推理、LongBench和上下文检索方面持续优于多种线性注意力变体。这些结果表明，内容路由的状态缓存显著增强了循环长程记忆，同时保留了其原生计算路径。

## Abstract
Transformers owe much of their strong long-context retrieval capability to a token-level memory that grows with context length. This flexibility, however, incurs a quadratic computation complexity during training and a key--value cache that grows linearly during autoregressive inference. Recurrent alternatives offer efficient decoding by compressing the entire history into a fixed-size state, but often underperform on recall-intensive tasks since earlier associations usually get overwritten by subsequent updates, and only the most recent contextual information is retained. In this paper, we introduce Memory-Anchor Routing across Context History (MARCH), a network architecture that effectively scales state-space models beyond a fixed-size dimension, while maintaining computational efficiency over long-sequences. MARCH periodically caches cumulative recurrent-state checkpoints as state anchors and associates each anchor with a compact, content-conditioned anchor key. This lets MARCH maintain a memory bank, which can grow as context length increases, providing a controllable trade-off between historical resolution and memory cost. At each token, MARCH produces an anchor query to attend all causally available state anchors, and the output is calculated as an attention-style aggregation over all historical anchors along the current state. We show that after standard pretraining, MARCH consistently outperforms multiple linear attention variants across commonsense reasoning, LongBench, and in-context retrieval. These results demonstrate that content-routed state caching substantially strengthens recurrent long-range memory while preserving its native computation path.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景冲突**：Transformer 依赖随上下文增长的 token 级 KV 缓存，具备强大长程检索能力，但训练复杂度为 O(T²)，推理时缓存线性增长；循环模型（如线性注意力、状态空间模型）将全部历史压缩为固定大小的状态，解码高效，但存在**固定状态瓶颈（fixed-state bottleneck）**——早期信息易被后续更新覆盖或衰减，模型无法直接从当前状态中恢复已被覆盖的旧关联。
- **现有改进的局限**：近年来的方法沿两个方向缓解状态瓶颈：① 容量扩展（增加单步状态维度，如混合状态、稀疏内存）；② 时间扩展（保留多个时间版本的状态，如对数层级结构、状态缓存）。然而，这些方法大多仍受限于有限或上界约束的总状态空间，且当存在多个历史状态时，**如何根据查询内容有效检索相关历史状态**这一问题尚未被充分探索。
- **核心研究问题**：能否在不修改底层循环更新机制的前提下，让模型按内容路由（content-routed）访问早期版本的循环记忆，从而突破固定状态瓶颈，同时保留循环模型的高效计算路径？
- **核心贡献**：提出 MARCH（Memory-Anchor Routing across Context History），通过在循环轨迹上周期性地缓存状态检查点作为“状态锚点”，并为每个锚点学习内容条件化的紧凑键，使模型能够在每个 token 处以注意力式聚合的方式检索历史状态，从而在固定状态循环模型之上建立**随上下文增长的记忆库**。

## 2. 论文提出的方法论

### 2.1 核心思想

- MARCH 将循环模型视为一个记忆系统，在原有循环更新路径之外，增加一条**“历史检索分支”**：周期性地保存当前循环状态的快照（状态锚点），并为每个快照构建一个内容相关的路由键；当前 token 生成路由查询，对所有可见锚点做 softmax 加权聚合，再将聚合结果读取为历史残差输出，与当前状态读出的输出相加。

### 2.2 关键技术细节

1. **状态锚点放置（Anchor Placement）**
   - 设文本序列为 T，锚定策略指定边界集合 B = {b₁, ..., b_M}，在每个边界后插入一个共享的锚点 token 位置 ξ_m。
   - 文本位置照常更新循环状态；锚点位置不改写状态，仅提供路由元数据（即锚点键）。

2. **累积状态检查点（Cumulative Checkpointing）**
   - 在边界 b_m 处，直接保存当前状态：A^(m) = S_(b_m)
   - 由于循环不在边界处重置，锚点 A^(m) 编码的是**从序列开头到 b_m 的累积前缀**，而非分段信息——这是“状态锚点”相对于分段缓存的核心区别。

3. **内容条件化的锚点元数据（Content-Conditioned Anchor Metadata）**
   - 锚点位置通过其隐藏表示 u_m 投影出查询 q_m，读取对齐的状态 A^(m)，并将读取结果通过输出投影和残差路径传导到下一层。
   - 同一表示 u_m 还被投影为紧凑路由键 κ_m = W_k u_m。
   - 由于 u_m^(ℓ+1) 依赖于 A^(m,ℓ)，**跨层之后路由键会携带锚点内容的状态信息**，而不仅是时间索引——这是实现“内容路由”而非“位置路由”的关键设计。

4. **内容路由与历史读取**
   - 对每个文本 token，定义路由查询 ρ_t = W_R x_t，计算与每个可见锚点键的点积得分 a_{t,m} = ρ_t^T κ_m。
   - 引入**空选项（null option）**，其负载固定为 0，允许模型在无需历史信息时旁路历史分支。
   - 对可见锚点+空选项做 softmax 得到路由概率 π，历史读出力为 Σ π_j · A^(j) · q_t。
   - 最终输出：o_t = S_t q_t + Σ π_j A^(j) q_t（当前状态读出力 + 历史读出力残差融合）。

5. **稀疏变体**
   - 可通过只保留得分最高的 Top-K 个可见锚点来降低聚合开销，实验表明性能损失较小。

6. **硬件高效实现**
   - 采用两阶段 producer–reader 计算：producer 按 Gated DeltaNet 的分块方式计算当前状态输出并做检查点；reader 受 FlashAttention 启发，联合分块锚点和查询，融合路由得分、online softmax 和加权状态读出的累加，避免物化稠密路由矩阵或候选读取张量。

## 6. 论文的主要结论与发现

1. **一致优于循环基线**：MARCH 在常识推理平均准确率上比 Gated DeltaNet 高 1.4 分（40.1→41.5），比 Log-Linear 变体高 1.5 分（40.0→41.5）；在 LongBench 上平均得分从 11.9/12.5 提升至 14.9（相对提升约 25%）。
2. **检索密集型任务增益显著**：在 NIAH 上，MARCH 在 24 个 task–length 组合中 19 胜 5 平；多针任务 11/12 胜。单针任务在 32K 外推时仍保持完美准确率，而 Transformer 和 Log-Linear 基线全部归零。
3. **上下文检索稳定提升**：在 6 个真实世界召回密集基准上平均相对提升 14%（20.5→23.3），最高 23%（TriviaQA）。
4. **固定间隔锚定的有效性**：C=512 在分辨率与成本间达到最佳平衡；推理时减小 chunk 可进一步提升检索质量（如 SQuAD 从 37.70 升至 40.35），但增加内存和路由开销。
5. **null 选项的必要性**：去掉 null 选项会降低所有指标，验证了“不需要历史时旁路”这一机制的价值。
6. **效率可控性**：Top-4 稀疏路由在常识推理和检索上几乎无损，主要代价体现在 NIAH 长程任务上；在 128K 长度下训练吞吐量超过 FlashAttention-2。
7. **外推能力优于注意力和对数基线**：由于路由器在所有锚点间共享参数，MARCH 在 32K 零样本外推时不受锚点数量限制，而 Log-Linear 的时间索引系数和 Transformer 的 RoPE 外推均出现失效。

## 7. 优点

1. **概念简洁且通用**：不改写底层循环更新、不修改 Gated DeltaNet 的内部状态动力学，只在其之上叠加“快照+路由”，因此可以泛化到任意线性注意力/SSM/循环模型之上。
2. **设计精妙的内容路由机制**：利用共享锚点 token 的跨层传导，使路由键在后续层中隐含锚点内容信息——这一设计实现了“按内容检索历史状态”而非“按位置/时间检索”，并将路由参数在所有历史锚点间共享，天然支持长度外推。
3. **兼顾效率与精度**：producer–reader 两阶段+融合 kernel 设计避免了中间张量物化；Top-K 稀疏路由提供可调的精度-效率折中。
4. **实验设计规范**：训练配置与基线完全匹配（数据、token 预算、上下文长度、优化设置），对比公平性较好；消融覆盖面广、设计针对核心机制。
5. **因果一致性与端到端可训练**：所有操作严格保持因果性，路由得分直接作用于输出，因此路由器和锚点键由标准语言模型目标端到端优化。
