## 摘要
混合注意力大语言模型将全注意力与循环线性注意力相结合，以降低长上下文推理成本，但其自回归解码仍受内存限制。树投机解码提供了一种有吸引力的加速路径，但现有的树投机系统是针对全注意力模型的键值缓存设计的。在混合模型上，它们逐分支遍历循环层，并为每个提议节点物化完整状态，导致验证延迟和瞬态内存随树大小和批量大小扩展性不佳。我们提出了Bole，一种内核与运行时协同设计，实现了混合注意力LLM的高效树投机。Bole将线性注意力循环转化为树结构闭式形式，并通过资源高效的GPU内核实现，并行验证所有提议节点，将线性注意力树验证加速3.4–7.7倍。它将投机状态更新无损编码为令牌级因子，仅重构采样后选中的状态，将瞬态状态内存减少82–99倍，释放GPU容量用于KV缓存。其集成到广泛部署的生产级LLM服务引擎SGLang中，将高效状态管理与针对完整混合前向校准的批量验证预算相结合。在四种模型、两个GPU平台和多样数据集上，Bole相比自回归解码实现了高达4.72倍的离线解码吞吐量，相比最强树投机基线实现了高达2.03倍的吞吐量。在在线代理工作负载下，相比最强树投机基线，其TTFT和TPOT分别降低了高达67.6%和49.9%。”}

## Abstract
Hybrid-attention large language models combine full attention with recurrent linear attention to reduce long-context inference costs, yet their autoregressive decoding remains memory-bound. Tree speculative decoding offers an attractive acceleration path, but existing tree-speculation systems are designed around the key--value caches of full-attention models. On hybrid models, they traverse recurrent layers branch by branch and materialize a full state for every proposal node, causing verification latency and transient memory to scale poorly with tree and batch sizes. We present Bole, a kernel--runtime co-design that enables efficient tree speculation for hybrid-attention LLMs. Bole transforms the linear-attention recurrence into a tree-structured closed form and realizes it with a resource-efficient GPU kernel, verifying all proposal nodes in parallel and accelerating linear-attention tree verification by 3.4--7.7$\times$. It losslessly encodes speculative state updates as token-level factors and reconstructs only the state selected after sampling, reducing transient state memory by 82--99$\times$ and freeing GPU capacity for KV caches. Its integration into SGLang, a widely deployed production LLM serving engine, couples efficient state management with a batch-wide verification budget calibrated to the complete hybrid forward. Across four models, two GPU platforms, and diverse datasets, Bole delivers up to $4.72\times$ the offline decode throughput of autoregressive decoding and up to $2.03\times$ that of the strongest tree-speculative baseline. Under online agent workloads, it reduces TTFT and TPOT by up to $67.6%$ and $49.9%$, respectively, over the strongest tree-speculative baseline.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：混合注意力大语言模型（Hybrid-Attention LLM）结合全注意力（full attention）与循环线性注意力（recurrent linear attention），以降低长上下文推理成本。典型代表如 Qwen3.5、Kimi Linear 等，均采用 Gated DeltaNet（GDN）等线性注意力层。
- **问题**：尽管混合注意力降低了每 token 服务成本，其自回归解码仍受内存带宽限制。树投机解码（Tree Speculative Decoding）是一种有效的加速手段，但现有树投机系统（如 SpecInfer、DeFT、SGLang 等）均针对全注意力模型的 KV 缓存设计，难以高效支持混合注意力模型。
- **具体瓶颈**：
  1. **串行递归**：在循环线性注意力层中，每个提议节点必须按其父节点的状态执行，导致树验证必须逐分支串行遍历，树越大，线性注意力耗时占比越高（从树的 8 节点到 64 节点，线性层占比从 4% 升至 27%）。
  2. **状态爆炸**：为每个提议节点物化完整的状态快照，瞬态内存随树大小和批大小线性增长。例如，在 Qwen3.5-122B-A10B 上，8 个请求各 32 节点时，快照占用 36 GiB，严重挤压 KV 缓存容量。
  3. **验证容量随硬件变化**：可高效验证的提议 token 数受 GPU 算力、内存带宽、KV 长度、树形状等多种因素影响，固定容量不可靠。
- **核心目标**：设计面向混合注意力 LLM 的高效树投机解码系统，实现并行验证、低内存开销和自动成本控制。

## 2. 方法论：核心思想、关键技术细节

Bole 是一个内核–运行时（kernel–runtime）协同设计，包含三大机制：

### 2.1 并行树求解器（Parallel Tree Solver）
- **核心思想**：将线性注意力的递归更新转化为树结构闭式解，使得所有提议节点可并行验证。
- **关键技术**：
  - 通过三个引理逐步推导出 Theorem 1 的闭式形式：
    - **Lemma 1（路径因子化状态）**：每个节点的状态可以分解为共享的前置状态 + 沿祖先路径的校正项之和。
    - **Lemma 2（祖先掩码校正系统）**：所有节点的校正向量构成一个线性系统 `(I + G)U = R`，其中 G 是严格下三角的祖先掩码矩阵。
    - **Lemma 3（深度有界幂零性）**：由于树深度有限，G 满足 `G^{d+1} = 0`，因此 `(I + G)^{-1}` 可以表示为有限多项式 `Σ_{m=0}^{d} (-G)^m`。
  - 最终闭式解为：`O = D_P Q S_pre + C(I + G)^{-1} D_β (V - D_P K S_pre)`。
  - 该闭式形式与顺序执行在代数上完全等价，无需逐节点递归遍历。

### 2.2 值分块并行验证内核（Value-Tiled Verification Kernel）
- **设计思路**：将值维度（dv）划分为多个块，每个 CTA 处理一个值块，而树因子（G、C）在所有块间共享。
- 执行流程：
  1. 因子构建（Factor Construction）：构造 G、C，只需要一次。
  2. 每个 CTA 读取 `S_pre` 和 `V`，沿 key 维度分块做矩阵乘，生成 `B_0` 和 `R`。
  3. 在片上执行有限 Neumann 序列：`Z^{(m+1)} = -G Z^{(m)}`，累加得到 `U`。
  4. 最终输出 `O = B_0 + C U`。
- 关键点：
  - 全程使用 Tensor Core 的规则矩阵运算，无节点级串行。
  - 中间结果（B_0、R、Z）不写回 HBM，仅输出 O 和 U。
  - 通过二维资源分块（值宽 bv + key 宽 bk）平衡并发度与单 CTA 效率。

### 2.3 因子化状态生命周期（Factorized State Lifecycle）
- **核心思想**：不再为每个分支保存完整状态快照，而是保留一个不可变的“提交状态”`S_pre`，并把候选分支的状态更新无损编码为 token 级因子（P、K、U）。
- **状态存储复杂度**：
  - 提交状态：`O(H d_k d_v)`
  - 树因子：`O(T H (d_k + d_v + 1))`
  - 相比快照的 `O(T H d_k d_v)`，减少了 82–99 倍。
- **提交过程**：采样确定接受路径后，仅对选中节点执行一次批量矩阵乘，重建新的状态 `S_new = P_a S_pre + (D_a K_a)^T U_a`，并覆盖原状态槽位。拒绝分支不需要回滚或占用缓存。
- **三种数据生命周期**：持久状态（请求）、轮级因子（到采样后）、层内临时量（G、C、Neumann 工作区）。

### 2.4 硬件感知的批量验证预算（Hardware-Aware Verification Budget）
- **动机**：目标前向中全注意力、线性注意力、MLP 等部分的成本随请求数、KV 长度、树形状等变化，且存在硬件相关的“近免费”区。
- **方法**：
  - 离线为每个配置（模型、GPU、批大小、KV 长度桶、树深度桶）扫描总验证节点数 N 的目标前向延迟，并选择满足 `T_ver(N) ≤ (1+ε)T_dec` 的最大 N 作为预算。
  - 在线运行时，按每个请求的草稿树节点的累计概率（路径概率积）做全局 top-k 选择，在预算内分配节点；由于子节点概率不可能超过父节点，所选节点自动保持前缀连通。

### 2.5 生产级集成（SGLang 集成）
- 基于 SGLang 实现，包含约 6.2k 行 Python/Triton 代码。
- 支持 CUDA Graphs：把选择、树打包、目标执行、采样、路径提交全部保留在 GPU 上，实现无气泡执行。
- 所有层（线性注意力层）的提交状态通过一次批量启动完成，与 KV 提交协同。

- **理论完备性**：从数学上严格证明了闭式解与顺序执行完全等价（无近似），并利用了 GDN 的幂零结构保证有限迭代。

- **在线负载单一**：只使用 Open-SWE-Traces 一种编码智能体工作负载，缺乏多种智能体场景或真实生产流量验证。
- **未讨论调度器与多租户复杂交互**：批量预算分配假设所有请求有平等的 SLO，未分析异质 SLO 下的效果（AdaServe 更侧重于 SLO 定制）。
- **实现依赖 SGLang 特定机制**：虽然内核设计有通用性，但状态管理、CUDA Graph 管线等与 SGLang 深度耦合，移植到其他引擎需要额外工作。
- **未报告生成质量影响**：虽然投机解码理论上保持输出分布不变，但未提供生成质量（如 MMLU、HumanEval 分数）的直接验证。
- **缺少大上下文极端场景**：实验中的 KV 长度范围未明确说明，长上下文（如 >100k）下的表现未知。
- **AdaServe 移植可能引入不公平**：由于原版不支持混合模型，移植过程中可能未完全捕捉其全部优化，对比结果可能存在轻微偏差。
