## 摘要
近期关于检索增强生成（RAG）的优化研究利用了块级KV缓存复用来避免处理长检索上下文以提高效率，但粗粒度块中仍存在显著的信息冗余和噪声。本文提出CoinRAG（面向长上下文RAG的上下文信息片段KV缓存复用），在低预填充延迟约束下优化帕累托前沿，同时最大化准确性。该名称隐喻地反映了我们的核心机制：就像将小令牌（或“硬币”）组合以累积更大的价值，CoinRAG以组合方式复用离线计算的细粒度片段缓存，以更语义相关且紧凑的方式高效形成学习到的上下文表示。具体而言，CoinRAG不是进行全块编码，而是通过两阶段检索识别检索块中与查询相关的语义单元，并将其切片KV表示与块级上下文无缝组装。在LongBench多跳问答任务上的广泛评估表明，CoinRAG显著降低了运营成本，并以新的帕累托前沿和标准快速预填充延迟预算下平均5.3%的答案质量（F1）相对提升优于其他基线。

## Abstract
Recent optimization studies on Retrieval-Augmented Generation (RAG) have exploited chunk-level KV cache reuse to avoid processing long retrieved contexts for higher efficiency, while significant information redundancy and noise still remain in the coarse-grained chunks. This paper optimizes the Pareto frontier under low prefill latency constraints while maximizing accuracy by proposing CoinRAG (Contextualized Information Nugget KV Cache Reuse for Long-Context RAG). The name metaphorically reflects our core mechanism: much like assembling small tokens (or "coins") to accumulate a larger value, CoinRAG compositionally reuses offline-computed, fine-grained nugget caches to form a learned contextual representation efficiently in a more semantically relevant but compact manner. Specifically, instead of full-chunk encoding, CoinRAG identifies query-relevant semantic units within retrieved chunks through two-stage retrieval and seamlessly assembles their sliced KV representations with a chunk-level context. Extensive evaluations on LongBench multi-hop question answering tasks demonstrate that CoinRAG significantly reduces operational costs and outperforms the other baselines with a new Pareto frontier and an average 5.3% relative improvement in answer quality (F1) under a standard fast prefill latency budget.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：检索增强生成（RAG）通过引入外部知识提升大模型的准确性和事实一致性，但在处理长检索上下文时，在线 prefill（预填充）计算开销巨大，导致高延迟和计算冗余。近期优化思路是通过**块级（chunk-level）KV 缓存复用**（如 TurboRAG、CacheBlend、KVLink）避免重复编码长文本，但这些方法仍以粗粒度块为单位，块内存在大量信息冗余和噪声。
- **核心问题**：如何在满足**低 prefill 延迟预算**（如 P99 TTFT < 100 ms，即用户可感知的交互式响应时间）的前提下，最大化 RAG 的答案质量？粗粒度块级缓存虽然省去了在线编码，但语义密度不足；细粒度表示又可能丢失上下文。
- **整体含义**：论文提出 CoinRAG，以“信息片段（nugget）”为粒度，离线预计算并复用 KV 缓存，在线只加载与查询相关的切片表示，从而在低延迟预算下同时提升准确率和效率——即在精度-延迟的 Pareto 前沿上取得新的优势。

## 2. 提出的方法论

- **核心思想**：将每个文档块离线编码为完整 KV 缓存，同时离线提取块内承载“信息 nugget”的文本片段（用起止 token 索引标识）；在线通过两阶段检索选出与查询最相关的 nugget，然后直接切片对应块的预计算 KV 缓存，经位置对齐后拼接成紧凑的上下文前缀，最后只对查询做一次在线编码。整个过程如同用小面额“硬币”拼出更大价值。
- **关键模块**：
  - **离线 Nugget 提取**（Algorithm 1）：用 GPT-4o-mini 对每个 512-token 块提出候选 nugget；通过“精确匹配 → 模糊匹配 → 放弃”三步将每个候选映射回原文中的 token 跨度，生成带边界索引的 nugget 集合。模糊匹配阈值 τ = 0.7。
  - **两阶段在线检索**：
    - 第一阶段：用稠密检索器（BGE-M3）从语料库取 top-k_c 个候选块；
    - 第二阶段：只在这些候选块内预提取的 nugget 中，按与查询的嵌入相似度排序，选 top-k 个 nugget。
    - 这样既能缩小候选范围，又避免直接在全库 nugget 上检索带来的噪声。
  - **上下文化 KV 缓存组合**：利用 nugget 的起止索引 [s_i, e_i] 从对应块的离线缓存 C_bi 中切片得到 C_bi[s_i:e_i]，保留整个块编码时的上下文语义，而非重新编码孤立文本。多个 nugget 切片通过 RoPE 位置旋转算子 Rot(C; Δ) 对齐位置，按原文档顺序连续拼接。第 i 个 nugget 的偏移量：Δ_i = |p| + Σ_{j<i}(e_j - s_j + 1)，其中 p 为系统提示。这样可消除位置间隙、压缩上下文长度。
  - **Nugget-Aware 微调**：为缓解“非连续片段拼接”与 LLM 预训练连续文本之间的结构gap，在训练时模拟在线组合过程，用检索出的 nugget 构造前缀上下文，并最小化目标答案的交叉熵损失。训练数据来自 IRCoT 的 277,280 个实例。

## 3. 实验设计

- **数据集 / 场景**：LongBench 中的三个多文档、多跳问答基准：HotpotQA、2WikiMQA、MuSiQue。每个数据集都提供了用于检索的文档语料，查询需要跨文档聚合和推理。
- **Baseline 对比**：
  - Standard RAG：在线编码全部检索文本 + 查询；
  - CacheBlend：部分在线重算以恢复跨块注意力；
  - TurboRAG（代表 Block-attention）：纯块级 KV 缓存复用；
  - KVLink：插入可训练链接 token 恢复跨块交互。
- **评估指标**：F1（答案质量，token 级）、TTFT（prefill 延迟，ms）、prefill token 长度（KV 内存代理）。
- **实验方式**：对每种方法扫描检索数量 k_c（或 nugget 数量 k），绘制 F1 vs 延迟预算、F1 vs 上下文长度预算的 Pareto 曲线；并报告 P99 延迟 ≤100 ms 与无延迟限制两种设定下的最好配置。消融实验对比：上下文化 vs 孤立 nugget 编码、两阶段 vs 一阶段检索、位置对齐有/无、微调有/无；另有成功与失败案例分类。

## 4. 资源与算力

- **硬件**：

  - 推理评估：单张 NVIDIA L40S（48 GB VRAM）；
  - 主机：双路 AMD EPYC 9354（64 核）、188 GB 内存、本地 NVMe SSD。
- **模型与工具**：GPT-4o-mini 做离线 nugget 提取（Batch API），BGE-M3 做稠密检索，Qwen2-7B-Instruct 作为生成模型。

  - KV 缓存构建：三个评估语料总耗时 <30 分钟，磁盘占用：HotpotQA 146 GB、2WikiMQA 75 GB、MuSiQue 173 GB；
  - Nugget-aware 微调：约 140 GPU-hours（单张 RTX PRO 6000），峰值显存 75.8 GB，训练 277,280 条实例，1 epoch，17,330 步。
- **KV 缓存规模**：每 512-token 块约 28 MB（bfloat16），nugget 覆盖约 70% 的块 token，因此实际加载更少。

## 6. 主要结论与发现

- **低延迟预算（P99 ≤ 100 ms）**：CoinRAG 在三个数据集上均优于所有基线，平均 F1 比最强对手 TurboRAG 高 5.3%（41.7 vs 39.6），同时上下文 token 长度短 1.84 倍。
- **无延迟限制**：CoinRAG 仍以平均 42.7 vs 40.6（+5.2%）超过 TurboRAG，且上下文长度短 6.8 倍；在 3 个数据集中有 2 个超过 TurboRAG。
- **Pareto 前沿**：在精度-延迟和精度-长度的两个维度上，CoinRAG 都给出了更优的前沿，表明细粒度 nugget 缓存复用能同时减少噪声和资源占用。
- **消融结论**：
  - 上下文化 KV 切片比孤立 nugget 编码显著更好（峰值 F1 提升 3.9–6.3 点）；
  - 两阶段检索优于一阶段检索（相对提升 9.6%–17.5%）；
  - 位置对齐在紧延迟预算（<75 ms）下收益明显，预算放宽后与不对齐持平；
  - 微调贡献最大（峰值 F1 提升 6.3–11.3 点），可弥合训练-推理结构gap。
- **整体判断**：低延迟 SLA 场景下，CoinRAG 带来的“去噪+紧凑化”增益超过了其缺失跨块交互造成的损失。

## 7. 优点

- **新颖的细粒度缓存复用粒度**：从“块”下沉到“nugget”，在保留块级上下文语义的同时显著压缩在线上下文长度，兼顾效率与精度。
- **工程化设计完整**：两阶段检索、跨度级切片、RoPE 位置对齐、nugget-aware 微调形成闭环，各组件均可解释、可消融。
- **实验严谨**：兼顾 F1、TTFT、上下文长度三个维度，绘制 Pareto 前沿并比较 P99 延迟；对基线进行复现和同数据训练，消融充分。
- **资源规划细致**：明确报告了离线提取、缓存构建、训练时长与磁盘占用，并设计了低 I/O 的缓存加载方式，使可行性透明。
- **应用价值明确**：在 100 ms 交互延迟 SLA 下获得更高准确率，同时降低 KV 内存，有利于提升并发吞吐。

## 8. 不足与局限

- **跨块注意力缺失**：不同 chunk 的 nugget 在编码时互不关注，与 TurboRAG 同型；可能损失需要跨文档交互才能捕捉的信息。
- **离线成本与静态假设**：需要一次性的大规模 nugget 提取、KV 缓存存储和微调；若语料更新频繁或模型升级，需要重新计算。
- **检索召回上界**：答案质量受限于两阶段检索能否找到正确证据；如果块级或 nugget 级检索失败，下游无法回答。
- **评估范围有限**：仅 3 个多跳 QA 数据集；未评估单跳、对话式、长文档生成等场景；也未考虑查询间缓存复用（连续查询共享文档）的收益。
- **基线覆盖不完整**：未与 GINGER/Crucible 等 nugget-based generation 方法直接比较；跨块交互方法只考虑了 CacheBlend，没有系统研究在 CoinRAG 中引入跨块注意力。
- **延迟度量简化**：TTFT 未显式区分磁盘 I/O 和计算，实际系统中 KV 加载的 I/O 可能成为新瓶颈，论文仅通过文件组织做了缓解。
