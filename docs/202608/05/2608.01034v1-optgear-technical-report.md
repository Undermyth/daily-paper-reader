## 摘要
我们推出了 Opt.Gear，这是一个为高效端侧部署、实时推理和强任务能力而设计的基础模型。它包含一个上下文长度为 64K 的稠密模型（1M、270M 和 1B）。我们设计了一种新的混合架构，将卷积键值门控混合器与局部-全局注意力相结合，以减少在长上下文中往往呈指数增长的 KV 缓存内存。该架构在 NPU 上的预填充和解码速度相比同规模模型最高可提升 X4.9 倍。Opt.Gear 从 2T 标记的候选语料库中，在一个精选的 0.5T 标记子集上进行训练，且不进行知识蒸馏。它是现有基础模型中数据效率最高的。所有模型均以开放的权重和部署二进制文件发布，支持 ONNX、Qualcomm NPU 和 Apple ANE，使 Opt.Gear 成为需要快速、内存高效推理和强任务能力的边缘应用的实用基础。此外，为扩展端侧生成语言模型的生态系统，我们推出了 Opt.Gear-1M，这是一个可部署在微控制器单元（MCU）上的微型语言模型（TLM）。Opt.Gear-1M 是首个在 STM32H747I-DISCO 的 ARM Cortex-M7 CPU 上通过 W4A32 量化实现 20 TPS 的生成语言模型。

## Abstract
We introduce Opt.Gear, a foundation model designed for efficient on-device deployment, real-tim inference, and strong task capability. It includes a dense model (1M, 270M, and 1B) with a context length of 64K. We designed a new hybrid architecture that combines a convolutional key-value gated mixer with local-global attention to reduce the KV-cache memory that tends to increase exponentially with long context. This architecture delivers up to X4.9 faster prefill and decoding speeds on the NPUs compared to models of a similar scale models. From a 2T tokens candidate corpus, Opt.Gear is trained on a curated 0.5T tokens subset without knowledge distillation. This is the most data-efficient of the existing foundation models. All models are released with open weights and deployment binaries for ONNX, Qualcomm NPU, and Apple ANE making Opt.Gear a practical base for edge applications that need fast, memory-efficient inference and strong task capabilities. Furthermore, to expand the ecosystem of on-device generative language models, we are introducing the Opt.Gear-1M that can be deployed on Micro-Controller Units (MCUs), a Tiny Language Model (TLM). Opt.Gear-1M is the first generative language model to achieve 20 TPS with W4A32 quantization on the ARM Cortex-M7 CPU of the STM32H747I-DISCO.

# Opt.Gear 技术报告：详细中文总结

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：如何在资源严格受限的设备端（如智能手机、嵌入式设备、MCU）高效部署大语言模型（LLM），同时兼顾推理速度、内存占用、长上下文能力和任务质量。
- **背景**：现有开源语言模型（如 Llama 3、Gemma 3）虽性能强大，但主要面向服务器级 GPU 设计，假设有高容量、高带宽内存和强大的加速器，难以直接部署到边缘设备。
- **关键瓶颈**：
  - **GQA（分组查询注意力）** 的计算复杂度为 O(N²)，随序列长度增长，给设备内存和算力带来巨大压力。
  - 自回归解码需要反复访问 KV-cache，其内存和带宽需求随上下文长度线性增长，成为移动端 NPU/GPU 的显著瓶颈。
  - 设备端硬件（SRAM 有限、内存带宽受限、异构 SoC 环境）对模型架构提出严苛要求。
- **整体含义**：本文的目标不是简单做“更小的模型”，而是通过硬件感知的架构设计，在模型质量、延迟、内存效率、长上下文能力和实际可部署性之间实现联合优化，满足边缘场景的低延迟、隐私保护、离线可用等需求。

## 2. 论文提出的方法论

### 核心思想
Opt.Gear 采用**混合架构**，将**卷积键值门控混合器（ConvKV-Gated Mixer）** 与**局部-全局注意力（GQA）** 结合，替代传统的滑动窗口局部注意力，从而在保留表达力的同时显著降低 KV-cache 开销。

### 关键技术细节

**（1）ConvKV-Gated Mixer——核心局部序列算子**

- 输入隐藏序列 X = [x₁, ..., x_T] ∈ ℝ^(T×d)，每个 token 先投影为 q、k、v 三个流：
  - q_t = x_t W_q, k_t = x_t W_k, v_t = x_t W_v
- 对 key 和 value 流执行**因果深度可分离 1D 卷积**：
  - k̃_t = Σᵢ aᵢ ⊙ k_{t-i}
  - ṽ_t = Σᵢ bᵢ ⊙ v_{t-i}
- 通过**逐元素门控**实现类注意力的内容相关更新：
  - g_t = σ(q_t ⊙ k̃_t)
  - y_t = g_t ⊙ ṽ_t
  - o_t = y_t W_o
- **关键优势**：无需求解逐 token 的注意力分数矩阵，也无需 softmax 归一化，避免自定义序列内核，更容易映射到边缘运行时。

**（2）内存高效缓存机制**

- 传统 GQA 缓存：Cache_global = O(2C·d_kv)
- 滑动窗口注意力缓存：Cache_local = O(2W·d_kv)
- ConvKV-Gated Mixer 的固定尺寸卷积状态缓冲：Cache_ConvKV = O(2L_conv·d_kv)，其中 L_conv 为卷积核大小（Opt.Gear-270M/1B 为 3，Opt.Gear-1M 为 4），与上下文长度无关。
- 预填充后，每个 ConvKV 层仅需保留最后的 L_conv 个投影 key/value 状态；解码时只需追加当前投射、丢弃最旧条目、执行固定缓冲区上的深度卷积。

**（3）模型配置**

| 配置项 | Opt.Gear-1B | Opt.Gear-270M | Opt.Gear-1M |
|---|---|---|---|
| d_model | 1,152 | 640 | 128 |
| 层数 | 26 | 18 | 5 |
| 注意力头 | GQA（4 查询头/1 KV 头） | GQA（4/1） | GQA（2/1） |
| 头部维度 | 256 | 256 | 64 |
| 卷积核大小 | 3 | 3 | 4 |
| 最大序列长度 | 65,536 | 65,536 | 512 |
| Tokenizer | KORMo（词汇 125,184） | KORMo | 自定义 BPE（词汇 2,048） |

- 采用混合注意力布局：少量全局注意力层（长程路由）+ 局部注意力层（中程上下文）+ ConvKV-Gated Mixer 层（短程混合）。
- 使用 QK-LN（查询-键归一化）、GeGLU / ReLU6GLU 门控 MLP、RoPE 旋转位置编码（全局 theta=1,000,000，局部 theta=10,000）。

**（4）量化感知训练（QAT）**

- 采用**基于校准激活的 Hessian 敏感度初始化**，以逐层输出重建为目标（类似 GPTQ）：
  - Δ* = argmin_Δ ‖WX − Q_Δ(W)X‖²_F
- 随后使用 **LSQ（Learned Step Size Quantization）** 细化分组缩放：
  - Ŵ_g = Δ_g · clip(round(W_g/Δ_g), q_min, q_max)
- 采用对称 INT4 分组（每组 32 个权重），前向传播模拟 W4A16 部署格式，避免训练-部署量化器失配。

## 6. 论文的主要结论与发现

1. **数据效率**：仅用 0.5T tokens（无蒸馏）即可达到甚至超越使用 2T–36T tokens、且依赖蒸馏的同规模模型，是“现有基础模型中数据效率最高的”。
2. **NPU 推理性能**：在 Qualcomm GEN5 NPU 上，Opt.Gear-1B 的 Prefill 速度达 7,042 tokens/s（Llama 3.2-1B 为 4,481、Gemma 3-1B 为 3,226），Decode 86 tokens/s；相比同类模型最高快 **4.9 倍**。
3. **内存效率**：ConvKV-Gated Mixer 将局部序列建模的缓存从 O(2W·d_kv) 降低到 O(2L_conv·d_kv)，消除了对上下文长度的依赖，显著减少长上下文解码时的内存带宽压力。
4. **MCU 可行性**：Opt.Gear-1M 在 STM32H747I-DISCO（Cortex-M7 @ 400MHz）上实现 **20 TPS**（W4A32 量化），是首个在 MCU 上达到交互式生成速度的生成语言模型，静态 RAM 占用约 449 KB。
5. **双语能力**：韩文基准上全面超越同规模 Gemma3、Llama3.2、EXAONE；特别是 HAERAE 上 Opt.Gear-1B 达 44.2%，显著领先。
6. **量化稳定性**：QAT 初始化的 Opt.Gear-1B 在后续 PTQ（RTN/AWQ/GPTQ）中性能下降极小，优于 Gemma3-1B 的大幅退化，且跨语言稳定性好。

## 7. 优点

- 硬件感知的架构设计：ConvKV-Gated Mixer 全部由静态线性、卷积和逐元素操作构成，避免动态 QKV 矩阵乘法和 softmax，天然适配 NPU 的矩阵单元和边缘运行时。
- 内存效率的精心设计：固定尺寸卷积状态代替序列长度相关的 KV-cache，从根本上缓解了长上下文解码的内存瓶颈。
- 清晰的训练策略：无知识蒸馏的 0.5T tokens 训练方案既实用（算力受限下的可行选择），又能更干净地归因架构和数据带来的增益。
- 全面的部署生态：开放权重 + ONNX / Qualcomm NPU / Apple ANE 二进制 + 支持 Transformers / llama.cpp / ExecuTorch / vLLM，覆盖从 MCU 到服务器的全谱系设备。
- QAT 方法严谨：基于 Hessian 校准激活的初始化 + LSQ 微调，统一训练/部署量化网格，避免量化器失配，效果上显著优于现有 PTQ 方法。
- 评测的透明性和公平性：明确标注各对比模型的训练数据规模和是否蒸馏，方便理解性能差异的来源。

## 8. 不足与局限

- **复杂推理能力受限**：受 0.5T tokens 训练预算制约，在数学和复杂推理任务上表现有限；论文明确承认当前结果无法区分推理差距来自模型规模、数据不足还是训练效率。
- **数据比例失衡**：仅 2% 数学数据、无代码数据，可能限制 STEM 相关任务表现；对推理能力提升构成瓶颈。
- **缺少消融实验**：未验证 ConvKV-Gated Mixer 各组件（卷积、门控、核大小）的独立贡献；未对比“仅 GQA”或“全注意力”的基线架构在质量与速度上的精确权衡。
- **Opt.Gear-1M 评估单薄**：仅针对 STM32 板控的合成数据任务（50K 对命令），缺乏通用能力或泛化性评估；最大序列长度 512 tokens 表明其仅适用于极短交互。
- **llama.cpp 的 NPU 性能异常**：Opt.Gear-1B 在 llama.cpp NPU 后端上 Prefill 仅 290 tokens/s（Gen5），远低于 QAIRT 的 7,042 tokens/s，论文将其归因于运行时对滑动窗口注意力的分配优化问题，但未深入验证，也提示了不同运行时的适配可能成为应用瓶颈。
- **硬件覆盖有限**：NPU 测试仅覆盖高通和 Apple，未覆盖如联发科、三星 Exynos NPU 等主流移动芯片；也未包括 x86 平台的边缘 GPU（如 Intel/NVIDIA 边缘设备）。
- **内存报告不完整**：MCU 上的 449KB 静态 RAM 占用中，bss 段（444KB）占总量的 99%，说明运行时工作区占用过高——在更小的 MCU 上可能无法部署，也意味着缓存机制的实际受益程度需更细致分析。
- **未报告功耗数据**：号称面向功耗敏感的设备端场景，但全文没有给出任何能耗/电源效率的实测结果。
- **上下文长度受限**：尽管声称 64K 上下文，但训练只是在后训练阶段用 20B tokens 扩展，长上下文的实际能力（如大海捞针测试）并未评估。
