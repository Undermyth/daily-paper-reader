## 摘要
AI代理正成为共享基础设施，然而持久性内存通常由独立的检索、治理和操作组件拼装而成。我们提出SuperLocalMemory 4.0，一个面向AI代理的受治理、本地优先的内存操作系统。该系统通过倒数排名融合整合了密集语义、BM25词法、时间性、Hopfield联想和扩散激活检索；包含受治理的学习与行为层；双时态召回；个人、共享和全局多范围内存；基于角色的访问控制；面向GDPR的导出与可验证擦除；审计轨迹；以及部署场景的EU AI Act检查清单。V4为其主写入路径引入了可靠性主干：生成围栏准入、策略注册表、具有逐投影应用/验证/补偿/擦除所有者的可验证内存事务，以及可哈希校验的完成清单。运行时可通过CLI、MCP、HTTP守护进程、仪表板、编辑器集成和框架适配器获得，并支持完全本地、本地带设备端模型以及提供商辅助模式。我们评估了十一个故障注入与机制场景，每个重复200次。已发布的证据包报告了2,200次确定性重复中的2,200次维护了其范围限定的组件属性。受治理写入信封在p50测得3.522毫秒，p99测得5.297毫秒，而未经治理的基线分别为1.835毫秒和2.569毫秒，对应进程内控制平面开销在p50为1.687毫秒，p99为2.728毫秒。这些是范围限定的组件与机制测量，并非端到端多进程或外部检索准确性基准。本文整合了先前SuperLocalMemory在隐私保护多代理内存、信息几何检索以及V3.3 Living Brain生命周期方面的工作。

## Abstract
AI agents are becoming shared infrastructure, yet durable memory is commonly assembled from separate retrieval, governance, and operational components. We present SuperLocalMemory 4.0, a governed, local-first memory operating system for AI agents. The system combines dense semantic, BM25 lexical, temporal, Hopfield-associative, and spreading-activation retrieval through reciprocal-rank fusion; a governed learning and behaviour layer; bi-temporal recall; multi-scope personal, shared, and global memory; role-based access control; GDPR-oriented export and verified erasure; audit trails; and a deployment-context EU AI Act checklist.   V4 introduces a reliability spine for its primary write path: generation-fenced admission, a policy registry, verifiable memory transactions with per-projection apply, verify, compensate, and erase owners, and hash-checkable completion manifests. The runtime is available through CLI, MCP, an HTTP daemon, a dashboard, editor integration, and framework adapters, and supports fully local, local-with-on-device-model, and provider-assisted modes.   We evaluate eleven fault-injection and mechanism scenarios, each repeated 200 times. The released evidence bundle reports 2,200 of 2,200 deterministic repetitions upholding their scoped component properties. The governed write envelope measured 3.522 ms at p50 and 5.297 ms at p99, versus 1.835 ms and 2.569 ms for the ungoverned baseline, corresponding to in-process control-plane overheads of 1.687 ms at p50 and 2.728 ms at p99. These are scoped component and mechanism measurements, not an end-to-end multi-process or external retrieval-accuracy benchmark. The paper consolidates prior SuperLocalMemory work on privacy-preserving multi-agent memory, information-geometric retrieval, and the V3.3 Living Brain lifecycle.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 体系架构（控制平面）
- 系统组织为**七个操作层（L1–L7）**：L1 准入层（身份解析、范围执行、幂等性检查、原始证据持久化）、L2 可查询核心（原子 SQLite 事务）、L3 富化（实体提取、场景构建、时间来源）、L4 记忆大脑（行为模式挖掘、软提示生成、技能演化）、L5 多通道检索、L6 上下文安全（策略评估、机密擦除、预算执行）、L7 运维（审计、缓存、压缩、网格协调、备份恢复）。
- 管理**六个 SQLite 存储文件**：`memory.db`（规范事实、FTS5、图/实体表、vec0、网格协调表）、`learning.db`、`audit_chain.db`（哈希链审计）、`pending.db`、`llmcache.db`、`admission_journal.db`（加密准入日志）。另有可选派生的 CozoDB 图和 LanceDB 向量存储。

### 2.2 多通道检索与信息几何底层
- **五路候选生产者**：密集语义（Fisher–Rao  geodesic 重打分，无方差信息时退化为余弦相似度）、BM25 词法、时间（双时态有效性过滤）、Hopfield 联想、扩散激活；随后经**带权倒数排名融合（Weighted RRF, k=15）** 融合，可选交叉编码器重排序、事件时间剪枝、证据下限与通道多样性检查。
- 引入信息几何基座（来自先前的 V3 工作）：sheaf-cohomology 一致性检查与 Riemannian–Langevin 生命周期模型；EbbinghausLangevinCoupling 类为实验性、无生产调用方。
- **时间感知**：每个事实携带三日期双时态模型（referenced / observation / interval）；`as_of` 参数贯穿所有召回表面；被取代事实仅做**降级**（0.25 倍评分因子、重排序），而非快照删除；Ebbinghaus 遗忘曲线 R(t)=e^(−t/S) 单调非增。

### 2.3 治理控制平面
- **不可变 ActorContext**（frozen dataclass）：完全由服务端认证状态派生（会话令牌、守护进程描述符、RBAC 结果），绝不是请求体字段；包含 principal_id、角色集合、profile 允许列表、传输通道、会话令牌哈希前缀（仅前 16 个十六进制字符用于审计归因）等。
- **操作策略注册表**（OperationPolicyRegistry）：18 种操作种类；`evaluate()` 纯 CPU 执行、无文件/网络/数据库访问；遵循 8 步决策链（kinds 解析 → 显式拒绝列表 → 策略查找（本地 fail-open、公司 fail-closed）→ 空角色拒绝 → **先认证再授权** → 角色不相交检查 → 传输通道检查 → 负载大小标注（仅建议、不拒绝））。
- **多范围隔离与代围栏**：profile（个人/团队/公司命名空间）× scope（personal/shared/global）双正交隔离轴；每行带 `profile_id` 分区键；**写时代围栏**（generation fence）拒绝来自已废弃 profile 绑定周期的重放写入。围栏是进程本地、TTL 300 秒的 (profile_id, idempotency_key)→epoch 映射；并发冲突时置为哨兵 _CONFLICT_EPOCH=-1，双请求均被拒绝。
- **GDPR**：`forget_profile` 三段式执行（审计先行（失败即整个擦除中止，fail-closed）→ 缓存/向量清理 → 全表 schema 检测删除）；残留行计数后才置 `erasure_complete=True`，任何错误强制置 0。
- **哈希链审计**（audit_chain.db）+ 侧车锚点（记录链长与头哈希）检测截断；EU AI Act 检查清单在所有模式下返回 `compliant=None`、风险类别"未定"——不做法律分类。

### 2.4 可靠性主干（V4 核心贡献）
1. **生成围栏准入（Generation-Fenced Admission）**：准入时记录 epoch 到围栏，写协调器执行时读取当前生成并比较，不匹配即抛 `ValueError("epoch is stale")` 包装为 `WriteCoordinatorError`，且在**任何投影写入器被调用之前**。
2. **可验证内存事务（Verifiable Memory Transactions）**：每次规范写操作在 `projection_obligations` 中为三个已注册投影所有者（Bm25Owner、TemporalOwner、VectorOwner）创建 PENDING 义务记录；每个所有者实现 apply/verify/compensate/erase/prove_erased/health 协议，校验和为 SHA-256；最后组装**完成清单（CompletionManifest）**，M037 能力数据库上用安装密钥导出的 HMAC-SHA256（v2）封印，拒绝降级到 v1；旧 schema 用无密钥 SHA-256（仅防意外损坏）。状态推导：COMPLETE（全部义务达到终态成功）/ DEGRADED（至少一个所有者失败、补偿已运行，**绝不静默提升**）/ FAILED（规范写入本身失败）。
3. **跨存储验证擦除**：每个所有者先插 tombstone，再执行物理删除，然后经 `prove_erased()` **活体物理重查**确认缺失（非重哈希包络），最终密封收据。
4. **SLM-Mesh 协调**：本地 SQLite 代理（mesh_* 表），提供经认证的对等消息、共享 KV 状态、带 TTL 与 fencing token 的建议锁；可选跨机器（leaderless、pull-based LWW 收敛按 (revision, node_id) 全序、TLS/证书固定/bearer/HMAC 传输）；明确声明**不是线性化共识、不是法定数复制、不是 CRDT 数据库**。

### 2.5 受治理技能演化（Governed Skill Evolution）
- 流水线：**筛选（screen）→ 确认（confirm）→ 变异（mutate）→ 盲验证（blind-verify）→ 持久化到隔离区（persist to quarantine）**。
- 预算控制：每次循环 30 分钟墙钟 / 10 次 LLM 调用 / 每天 3 个循环，预算耗尽即失败关闭（fail-closed）。
- 防循环：哈希去重 + 尝试次数上限；盲验证中验证器与生成器信息隔离，且看不到原始技能；验证器与生成器模型不同时记录独立性降低。
- 范围：默认停在"已验证隔离区"；`auto_approve`（配置门，非人工或 RBAC 审批）可原子提升技能至活跃加载器并支持失败回滚；父版本谱系与代跟踪未报告。

- 性能测量：延迟 n=300；并发 1–16 线程；内存轨迹 60 秒；治理开销 n=1,000（p50/p95/p99）。
- 检索质量：V3 架构 LoCoMo（非 V4 重跑），含信息几何消融（+12.7 pp）。
- 对照/消融：exp5 含阳性对照；exp2 与 exp2b（合成替身 vs 真实所有者）形成结构对照；信息几何消融。

### 充分性与客观性评估
- **优势**：作为组件级故障注入与机制验证，实验较为系统；每个场景均有明确 scope 声明；重复旨在检测**确定性 flakiness**而非统计抽样，作者明确不报告置信区间或推断失败概率——这在方法学上是诚实且恰当的。
- **缺口**：
  - **非端到端**：无单个场景覆盖完整 HTTP 认证 → ActorContext → 日志 → 围栏 → 所有者 → 义务分类账 → 清单 → ANN 的全链路；传输、多进程、网格、长期部署故障注入均为未来工作。
  - **无新的 V4 检索基准**：LoCoMo 结果是 V3 架构携带，未在 V4 发布物上重跑验证。
  - **环境限制**：sql
