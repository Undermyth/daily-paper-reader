## 摘要
线性注意力模型通过用循环状态更新替代逐对词元交互，消除了softmax注意力的二次方前缀计算和不断增长的KV缓存。然而，现有的解码实现通常在生成每个词元后物化并写回完整的循环状态，使得状态维护成为内存流量的主要来源，尤其对于具有大状态和多头数的模型。本文提出DeltaLog，一种在不改变模型语义的情况下减少这种开销的循环状态解码方案。具体而言，DeltaLog将循环状态表示为稠密基状态以及最近紧凑更新的有界日志。大多数解码步骤仅将紧凑的更新因子追加到该日志中，而周期性的合并步骤将累积的更新折回到稠密基状态中。因此，模型观察到与急切解码相同的稠密状态，但大多数全状态写回被轻量级追加操作所取代。我们为GDN、KDA和RWKV6实现了DeltaLog，并将其集成到原型服务栈中。在这些模型中，DeltaLog将循环状态更新内核加速高达$1.86\times$，将分析得到的循环状态写流量减少高达$7.83\times$，并相对于稠密循环基线实现了$1.05$--$1.20\times$的端到端服务加速。

## Abstract
Linear attention models eliminate the quadratic prefix computation and context-growing KV cache of softmax attention by replacing pairwise token interactions with recurrent state updates. However, existing decoding implementations often materialize and write back the full recurrent state after every generated token, making state maintenance a major source of memory traffic, especially for models with large states and many heads. This paper presents DeltaLog, a recurrent-state decoding scheme that reduces this overhead without changing the model semantics. Specifically, DeltaLog represents the recurrent state as a dense base state together with a bounded log of recent compact updates. Most decode steps append only compact update factors to this log, while periodic merge steps fold the accumulated updates back into the dense base state. Thus, the model observes the same dense state as in eager decoding, but most full-state write-backs are replaced by lightweight append operations. We implement DeltaLog for GDN, KDA, and RWKV6 and integrate it into a prototype serving stack. Across these models, DeltaLog accelerates the recurrent-state update kernel by up to $1.86\times$, reduces profiled recurrent-state write traffic by up to $7.83\times$, and achieves $1.05$--$1.20\times$ end-to-end serving speedups over dense recurrent baselines.

## 1. 论文核心问题与研究动机

- **背景问题**：线性注意力模型（Linear Attention）用固定大小的循环状态替代了 softmax 注意力中与上下文长度线性增长的 KV 缓存，避免了前缀计算的二次复杂度。但在**自回归解码**阶段，每生成一个 token 都必须读取并写回完整的稠密循环状态，状态张量为 $[B, H, d_k, d_v]$。
- **核心矛盾（状态更新税，State-Update Tax）**：一个新 token 对状态的实际贡献仅为外积形式 `$a_t b_t^\top$`，数据量只有 $O(BH(d_k + d_v))$；但急切物化（eager materialization）需要读写 $O(BH d_k d_v)$ 个元素，产生了严重的**写放大**。
- **量化证据**：
  - Roofline 分析表明，稠密状态更新的算术强度仅约 0.5–1.0 FLOPs/byte，远低于 H200 类 GPU 的机器平衡点（约 208 FLOPs/byte），属于强内存受限操作。
  - 在 Qwen3.6-35B-A3B 上实测，循环状态物化占完整解码延迟的比例随批大小增长：上下文 1k 时从 $B=64$ 的 25.2% 升至 $B=256$ 的 44.6%，说明该开销可成为一阶服务瓶颈。
- **总体含义**：瓶颈不在于循环更新本身，而在于**物理物化策略**——每步急切写回稠密状态是不必要的，可以通过延迟物化来避免。

## 2. 方法论：DeltaLog

### 2.1 核心思想

- 将循环状态分解为两部分：
  - **稠密基状态**（dense base state）$\bar{S}$：存储较旧的历史信息；
  - **有界更新日志**（bounded update log）：存储最近的紧凑更新因子。
- **追加（append）步骤**（大多数解码步）：只将紧凑因子 `$(a_t, b_t, \bar{\ell})$` 追加到日志中，稠密基状态保持不变，避免全状态写回。
- **合并（merge）步骤**（每 $M$ 步一次）：将累积的日志条目折算回稠密基状态，重置日志。
- 合并区间 $M$ 决定了延迟物化的程度：$M$ 越大，稠密写回越少，但日志回放（replay）开销越大，因此存在最优区间。

### 2.2 关键公式与状态不变式

- 统一建模了多种线性注意力变体，解码步可写作：

$$S_t = D(\lambda_t) S_{t-1} + a_t b_t^\top, \quad o_t = \phi(q_t)^\top S_t$$

其中 $D(\lambda_t) = \mathrm{diag}(\exp(\lambda_t))$ 为对角衰减，不同模型（Linear Attention、RetNet、GLA、RWKV6、GDN、KDA）的区别仅在于衰减粒度和更新语义。

- DeltaLog 的状态不变式：物理状态（基态 + 日志）在任何时刻都逻辑等价于急切解码的稠密状态：

$$S_t = D(\bar{\ell})\bar{S} + \sum_{i=0}^{L-1} D(\bar{\ell} - \Lambda_{\log}[i]) K_{\log}[i] U_{\log}[i]^\top$$

- **合并步骤的数学操作**：

$$\bar{S} \leftarrow D(\bar{\ell})\bar{S} + \sum_{i=0}^{L-1} D(\bar{\ell} - \Lambda_{\log}[i]) K_{\log}[i] U_{\log}[i]^\top + a_t b_t^\top$$

- **闭包性保证**：作者证明了追加和合并两种操作均保持状态不变式，因此在精确算术下 DeltaLog 与急切稠密解码**代数等价**，不改变模型权重或逻辑循环。
- **流量模型**：DeltaLog 的每步状态相关流量约为：

$$T_{\text{delta}} \approx T_{\text{common}} + C_{\text{state}} + \frac{C_{\text{state}}}{M} + C_{\text{log}}(M) + 2C_{\text{decay}}$$

优势条件为：避免的稠密写流量 $C_{\text{state}}(1 - 1/M)$ 大于新增的日志与元数据流量。

### 2.3 内核级实现

- **按值维度分块（value tiling）**：将每头状态沿 $d_v$ 维划分为多个瓦片，每个工作单元拥有一个稠密基态瓦片及其对应的值侧日志分片；键侧因子和衰减元数据在所有值瓦片间共享，避免冗余写入。
- **三阶段追加路径**：
  - `ReplayPrep`：每个 slot-head 对计算一次键侧重放系数（FP32 暂存）；
  - `AppendDecode`：各值瓦片并行流式读取基态瓦片、复用重放系数、计算输出切片并追加值侧日志分片；
  - `Finalize`：单一写者提交共享元数据（键侧因子、衰减快照、日志长度）。
- **算子实例化差异**：
  - **GDN**：头级标量衰减 + Delta 规则修正，日志元数据最紧凑，收益最大；
  - **KDA**：逐键衰减 + Delta 规则修正，元数据和重放算术增加；
  - **RWKV6**：逐键衰减但无修正路径，更新路径简单。

## 7. 方法优点

- **语义零改变**：只改变物理调度，不修改任何模型权重或逻辑循环方程，精确算术下与期望实现严格等价，且有形式化证明。
- **优雅的抽象**：统一建模了标量衰减、对角衰减、Delta 规则修正等多种变体，只需调整日志数据的存储精度和重放计算方式。
- **系统化内核设计**：值分块 + 单写者协调 + ReplayPrep/AppendDecode/Finalize 三阶段流水，兼顾并行度和元数据一致性；split-replay 消融显示了内核组织对性能的量化影响。
- **实验证据链完整**：从 roofline 理论分析 → 内核延迟 → 硬件计数器流量验证 → 敏感性分析 → 端到端服务，逐层递进，机制主张有直接数据支撑。
- **数值精度设计细致**：关键路径（值侧日志）使用 FP32 保留精度，非关键路径（键侧日志）可用 BF16 压缩，精确性有 rollout 实验支撑。

## 8. 不足与局限

- **适用场景受限**：优化收益集中在**大 batch、大状态**的解码场景。小状态（如 KDA 在 128 MiB 时仅 1.02 倍加速）或小 batch 下，日志重放和元数据开销可能抵消节省的写流量，甚至在极端情况下变慢。
- **合并区间选择依赖经验**：最优 $M$ 随算子、批大小、硬件而异，论文未给出自适应选择策略，实际部署需额外调参。
- **端到端收益有限**：受 Amdahl 定律约束，优化范围仅为循环状态更新路径，1.05–1.20 倍的整体加速较为温和。论文未讨论若与算子融合、MLP 优化、调度优化联合使用时的潜在叠加效应。
- **服务集成验证范围窄**：仅在 batch-synchronous、CUDA 图模式的单机服务栈中验证，未覆盖连续批处理下的复杂交错场景、多节点部署、prefix caching 等实际生产特性。
- **混合精度风险**：虽然数值误差满足 1% 容差，但长期生成中误差是否会累积未做长序列稳定性测试。
- **对比广度不足**：未与 KVBuffer （同领域工作，参考文献 [37]）等优化方法对比；RWKV6 端到端效果未验证。
