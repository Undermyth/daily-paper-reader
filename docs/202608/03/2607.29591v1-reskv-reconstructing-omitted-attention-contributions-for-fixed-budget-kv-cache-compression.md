## 摘要
KV缓存压缩对于高效的长上下文推理至关重要。现有的驱逐方法会永久丢弃未选中的token，从而移除它们对注意力的总体贡献。基于合并的替代方案保留了更多信息，但可能扰动应保持精确的保留键和值。我们观察到，缓存驱逐所遗漏的信息可以表述为softmax注意力分子和分母中的残差统计量。基于这一观察，我们提出了ResKV，它将固定的KV预算划分为一个精确的主缓存和一个紧凑的残差缓存，用于重构被忽略token的贡献。ResKV让主缓存token和残差条目参与相同的softmax归一化，因此残差条目同时恢复注意力分子和分母的质量，而不是作为事后修正。构建时的验证代理确定每层和每个KV头的残差分配，而解码时的动态门控调整每个查询的残差贡献。在LongBench和RULER上的全面评估，涵盖查询感知和查询无关设置、多个骨干网络、缓存预算和代表性压缩基线，表明在相同保留KV预算下取得了广泛改进，同时保持了压缩解码的实际效率，包括峰值内存使用和长上下文解码吞吐量。

## Abstract
KV cache compression is essential for efficient long-context inference. Existing eviction methods permanently discard unselected tokens and consequently remove their aggregate contribution to attention. Merging-based alternatives preserve more information but can perturb retained keys and values that should remain exact. We observe that the information omitted by cache eviction can be formulated as residual statistics in both the numerator and denominator of softmax attention. Based on this observation, we propose ResKV, which divides a fixed KV budget into an exact main cache and a compact residual cache that reconstructs the contribution of omitted tokens. ResKV lets main-cache tokens and residual entries participate in the same softmax normalization, so residual entries restore both attention numerator and denominator mass rather than acting as a post-hoc correction. A construction-time validation proxy determines residual allocation for each layer and KV head, while a decode-time dynamic gate adjusts residual contributions for individual queries. Comprehensive evaluations on LongBench and RULER, covering query-aware and query-agnostic settings, multiple backbones, cache budgets, and representative compression baselines, demonstrate broad improvements under the same retained KV budget while preserving the practical efficiency of compressed decoding, including peak memory usage and long-context decode throughput.

# ResKV：重构被忽略的注意力贡献以实现固定预算KV缓存压缩

## 1. 核心问题与研究动机

**核心问题**：长上下文大语言模型（LLM）推理中，KV缓存随上下文长度线性增长，成为内存占用和带宽开销的主要瓶颈；而现有KV缓存压缩方法面临"精度 vs. 效率"的根本矛盾。

**现有方法的两大缺陷**：
- **驱逐方法**（如 H2O、SnapKV、AdaKV 等）：评分后保留部分 token、永久丢弃其余，导致被丢弃 token 的注意力聚合贡献（分子和分母质量）彻底丢失。在注意力分布较分散的场景下，大量低分 token 的聚合贡献可能相当可观。
- **合并方法**（如 CaM、KVMerger 等）：虽将被驱逐信息折叠进保留槽位，但会扰动本应精确保留的 key 和 value，损害尖锐检索任务所需的精确记忆。

**关键观察**：驱逐所丢失的信息可以精确表述为 softmax 注意力中分子与分母的"残差统计量"（residual statistics）——即被驱逐集合 E 上的两组未归一化 softmax 和式。由此，研究者提出一种更优的压缩范式：与其在"完全删除"和"折入保留槽位"之间二选一，不如在固定预算下用一个紧凑的残差缓存来**重构**这部分被忽略的注意力贡献。

## 2. 方法论

### 2.1 核心思想：主缓存 + 残差缓存

ResKV 将固定 KV 预算 b = m + r 划分为两部分：
- **主缓存（Main Cache, M）**：m 个槽位，以原始 key/value 精确存储高优先级 token，不进行任何修改；
- **残差缓存（Residual Cache, R）**：r 个槽位，以紧凑的"代表条目"总结被驱逐 token 集合 E 的信息，用于重构其注意力贡献。

### 2.2 数学形式化

**残差定义**：给定主缓存 M，残差 R(M; q) = (N_E(q), Z_E(q))，其中：
- Z_E(q) = Σ_{p∈E} e^{a_p(q)}（分母贡献）
- N_E(q) = Σ_{p∈E} e^{a_p(q)} v_p（分子贡献）

理论上，将残差加回即可恢复完整注意力：o_S(q) = (N_M + N_E)/(Z_M + Z_E)。但残差权重 e^{a_p(q)} 依赖未来查询 q，无法直接缓存，因此 ResKV 使用"键空间一致性"作为查询无关的代理：**距离相近的键往往诱导相似 logit，可用一个代表项近似一组 token**。

**残差条目构造**：将 E 划分为 r 个簇（Lloyd 迭代求解，目标为簇内 k 的平方距离最小化），每个簇 C_j 存储三个量：
- 均值键 k̄_j（代表地址/逻辑）
- 均值值 v̄_j（代表输出内容）
- 数量 c_j（代表 softmax 质量）

近似公式：Σ_{p∈C_j} e^{a_p(q)} ≈ c_j · e^{ā_j(q)}，其中 ā_j(q) = ⟨q, k̄_j⟩/√d。

### 2.3 共享 Softmax 残差解码

与传统的"输出后修正"不同，ResKV 的残差条目与主缓存 token **参与同一个 softmax 归一化**。残差条目 logit 设计为：
- ã_j = ⟨q, k̄_j⟩/√d + log c_j + log g(q)

其中 log c_j 注入群体数量质量，log g(q) 为动态门控。最终输出为：
- ô(q) = (Σ_{p∈M} e^{a_p} v_p + Σ_{j∈R} e^{ã_j} v̄_j) / (Σ_{p∈M} e^{a_p} + Σ_{j∈R} e^{ã_j})

这样每个残差条目同时恢复分子质量和分母质量。当 r=0 时退化为纯驱逐。

### 2.4 自适应残差控制（两个关键机制）

1. **构建期验证代理**：每个候选残差预算 r 在验证集上计算残差增强输出与完整缓存输出的重构误差；只有当残差缓存的验证损失比纯主缓存改善超过 δ=1% 相对裕度时才启用残差分配，实现了**逐层、逐 KV 头的自适应预算分配**。
2. **解码期动态门控**：根据主缓存注意力的最 sharp 权重 p_max^M(q) 动态调节残差 logit（通过 sigmoid 函数 g(q) 缩放）。主缓存注意力集中时降低残差贡献以保护尖锐检索峰，注意力分散时增加残差贡献以恢复聚合信息。

## 3. 实验设计

### 3.1 基准与数据集

- **LongBench**：16 个真实世界长上下文理解任务，涵盖单文档/多文档 QA、摘要、少样本学习、合成检索、代码补全等。
- **RULER**：13 个受控长上下文任务（检索类和聚合类），在 4K 和 32K 两种上下文长度下评估。

### 3.2 骨干模型

- LLaMA-3.1-8B-Instruct
- Qwen-2.5-7B-Instruct

两者均为 GQA（分组查询注意力）架构。

### 3.3 对比基线

- **H2O**：高累积注意力质量 token 保留
- **SnapKV**：观察窗口估计 token 重要性
- **TOVA**：基于近期注意力评分
- **AdaKV**：跨注意力头自适应预算分配
- **CaM**：合并式压缩方法（对比合并范式）

### 3.4 设置

- 压缩比率 ρ ∈ {0.6, 0.7, 0.8, 0.9}（对应保留 40%、30%、20%、10% KV 槽位）

## 6. 主要结论与发现

1. **有效性**：ResKV 在**所有 32 个 LongBench 配置**和 **63/64 个 RULER 配置**上超越了对应基线，证明其方法在各类任务上均有收益。
2. **预算越紧，收益越大**：在 10% 和 20% 保留预算下 RULER 平均提升达 3.47 和 3.66 分（查询无关设置），说明残差重构在极端压缩下尤其有效。
3. **查询无关设置提升更显著**：RULER 查询无关设置平均提升 4.54 分，显著高于查询感知的 2.22 分——这更好地匹配真实部署场景。
4. **任务类型差异**：提升集中在代码补全、多键检索、可变跟踪（VT）、FWE 等依赖分布式证据的任务，与小精确缓存 + 残差重构的设计假设一致。
5. **与合并方法的对比**：相比 CaM 的不稳定收益，ResKV 提供更强且更稳定的改进，支持"独立残差优于折入合并"的设计选择。
6. **效率可接受**：峰值内存几乎与压缩基线重叠，吞吐量低于 SnapKV 但远高于完整缓存，且全缓存 128K 时 OOM 而 ResKV 仍保持稳定解码。

## 7. 优点

1. **切入角度新颖且数学严谨**：将驱逐操作表述为 softmax 中可量化的"残差"形式（分子和分母），为该问题提供了清晰的理论框架，附录还给出了残差近似的误差界（基于组内 logit 偏差 η 的指数界）。
2. **设计优雅、模块化强**：主缓存完全精确 + 残差缓存参与同一 softmax，概念简洁，且可无缝叠加在任何现有驱逐方法之上（无需改变基线的评分/分配规则），实际价值高。
3. **自适应性强**：构建期验证代理按层、按注意力头自动决定残差分配；解码期动态门控按查询调节贡献，两个机制设计精巧、互为补充。
4. **实验覆盖面广且诚实**：同时报告查询感知/查询无关两种设置、多骨干、多预算、多基线，并包含与合并方法的对比；效率分析（内存与吞吐）验证了实际可用性。
5. **理论分析完整**：附录给出主-残差分解的精确输出差异公式、残差条目误差界，以及两个控制机制的数学描述。
6. **对 GQA 和 FlashAttention 的优化做了适配**：通过 log-sum-exp 统计量将残差分支融入共享 softmax，兼顾了系统效率。

## 8. 不足与局限

1. **骨干覆盖有限**：仅在 7B-8B 规模的 GQA 指令模型上验证，未覆盖更大规模模型（如 70B）、非 GQA 架构或非指令模型，泛化结论有限。
2. **每种配置仅运行一次**：无多次运行的标准差，无法判断改进是否统计显著，存在随机性风险（虽然固定种子）。
3. **构建期开销未充分评估**：验证代理需要在观察窗口中为每个候选残差预算计算前向重构误差，涉及额外计算；论文未报告预填充阶段的耗时开销。
4. **残差条目使用均值键值过于简单**：当簇内 logit 偏差较大时近似误差会指数增长；论文仅用 Lloyd 聚类不保证最优分组，更丰富的残差摘要（如低秩近似、多中心）可能进一步提升。
5. **单次压缩、无更新机制**：残差缓存构建后在整个生成期间不刷新，长生成场景下可能性能下降；论文也承认这是未来工作。
6. **吞吐量代价未完全消除**：解码阶段需额外评估残差分支并计算动态门控，相对纯驱逐有中等吞吐损失（虽然全缓存优势明显），专门的核融合可进一步优化。
7. **动态门控的阈值和温度是超参数**：τ = 0.25、T_g = 1/12 等参数未做敏感性分析，实际部署需重新调参。
8. **无更大批量服务负载测试**：仅在单序列或小批量场景下评估，服务场景下吞吐和内存行为可能不同。

## 总结

ResKV 通过将一个固定 KV 预算拆分为"精确主缓存 + 紧凑残差缓存"的表示范式，在理论上将驱逐损失嵌入 softmax 残差形式，在工程上用验证代理和动态门控实现自适应控制，在实践上证明了与现有驱逐方法正交叠加即可获得显著且一致的收益——所有 LongBench 配置和绝大多数 RULER 配置上的提升、极小的内存开销和可接受吞吐代价，使其成为当前 KV 缓存压缩家族中一种具有较高实用价值和良好理论基础的方案。未来工作可沿着更多模型/架构覆盖、残差更新机制、更丰富的残差摘要和专用核融合方向展开。
